# 八股题库 · 05 信号完整性 SI（Signal Integrity）

> **先进工艺的"必考题"**。7nm 以下工艺，信号完整性已经从"加分项"变成"必会项"。
> 本专题 10 道题，覆盖串扰 Crosstalk、毛刺 Glitch、SI-Delta、Shielding、CES、Hold 修复。

---

## 一、核心概念速查

### 1.1 串扰（Crosstalk）

**定义**：相邻走线之间通过**互容（Cc）和互感（Lm）**的电磁耦合，导致一根线的信号干扰另一根。

**两个核心影响**：

| 影响 | 表现 | 原因 |
|---|---|---|
| **Glitch（毛刺）** | 静态线上出现意外脉冲 | 邻线翻转通过 Cc 注入电荷 |
| **Delay Change（延迟变化）** | 翻转时间变长或变短 | 邻线翻转方向同/反向，电流叠加或抵消 |

**两个关键系数**：

| 系数 | 含义 | 典型值 |
|---|---|---|
| **Kc（耦合电容比）** | `Cc / (Cc + Cg)` | 7nm 工艺常 > 0.4（强耦合） |
| **Victim/Aggressor 比例** | 受害线/攻击线数 | 1:N 影响量级 |

### 1.2 SI Delta

**定义**：考虑串扰前后的 delay 变化量。

```
SI Delta = Delay_with_crosstalk - Delay_without_crosstalk
```

**两种场景**：

| 场景 | 邻线翻转方向 | SI Delta | 对 setup/hold 的影响 |
|---|---|---|---|
| 同向翻转（BEST）| 与 victim 同时翻转 | 负 | delay 变短（**hold 变难**）|
| 反向翻转（WORST）| 与 victim 反向翻转 | 正 | delay 变长（**setup 变难**）|

### 1.3 Shielding

**Shielding**（屏蔽）：在攻击线和受害线之间插入**VDD/VSS 走线**，切断耦合。

**三种方式**：

| 方式 | 实现 | 代价 |
|---|---|---|
| **Co-axial Shielding** | 攻击线两侧全程 VSS/VDD | 占 routing 资源最大 |
| **Shield Net 标注** | 工具自动把同层相邻线连成 shield | 资源中等 |
| **Spare Cell / Power Strap** | 在 cross-over 处放 power | 资源最少 |

## 二、10 道高频面试题

### 题 1：什么是串扰？Crosstalk 通过什么物理机制作用？

**参考答案**：

**串扰（Crosstalk）**：相邻走线之间的**电磁耦合**，导致一根走线（victim）的信号被另一根（aggressor）干扰。

**两种物理机制**：

| 机制 | 路径 | 效果 |
|---|---|---|
| **互容 Cc（Capacitive Coupling）** | 平行走线间电场 | 在 victim 上注入电荷 → glitch / delay 变化 |
| **互感 Lm（Inductive Coupling）** | 走线间磁场 | 产生感应电压 → 抖动 |

**比例关系**：
- 7nm 以下 Cc 占主导（**密集走线、电容耦合强**）
- 28nm 以上 Lm 开始有影响
- 微波/射频频段 Lm 主导

**驱动电压差与耦合强度的关系**：
- 越长（Cc 累计越大）→ 串扰越强
- 越近（间距越小）→ 串扰越强
- 平行长度 > 临界值（约 50μm @ 7nm）→ 显著

**加分点**：
- 提到 "耦合系数 Kc = Cc / (Cc + Cg + Cp)，Kc 越大串扰越严重"
- 提到 "5nm/3nm 工艺，Kc 经常 > 0.5，传统 spacing 解决不了"
- 提到 "不同金属层之间也存在 Cc（如 M1 与 M2 平行），不限于同层"

---

### 题 2：Crosstalk 在 Setup 和 Hold 检查中分别怎么体现？

**参考答案**：

| 检查 | 关心场景 | SI Delta 方向 | 分析方式 |
|---|---|---|---|
| **Setup 检查** | WORST case（邻线反向翻转）| delay 变长 | 看 max delay 是否还满足 setup |
| **Hold 检查** | BEST case（邻线同向翻转）| delay 变短 | 看 min delay 是否还满足 hold |

**为什么 Setup 关心 WORST？**
- Setup 关心最坏情况：数据到达晚了（延迟大）→ 必失败
- 邻线反向 → 电流被"抵消" → 充放电更慢 → delay 增大
- 工具用 SI-DPV 跑 worst corner 仿真

**为什么 Hold 关心 BEST？**
- Hold 关心最快情况：数据到太快 → 越过 latch 的 hold window
- 邻线同向 → 电流叠加 → 充放电更快 → delay 减小
- 工具用 SI-Hold 跑 best corner 仿真

**加分点**：
- 提到 "Hold 违例修复比 Setup 难——通常需要加 buffer 增加 delay"
- 提到 "先进工艺 SI 在 setup 上比 hold 严重——delay 波动大"
- 提到 "PrimeTime-SI / Tempus SI 是 sign-off 必跑"

---

### 题 3：什么是 SI Delta？怎么让工具在 STA 时考虑它？

**参考答案**：

**SI Delta**：考虑串扰后 cell delay 的变化量。

```
Delay_with_SI = Delay_without_SI + SI_Delta
```

**工具怎么考虑 SI**：

1. **PrimeTime-SI / Tempus SI**：
 - 读 SPEF（带耦合电容信息）
 - 跑 SPEF + Liberty + VCD 仿真
 - 找到每条 net 的 aggressor
 - 计算 worst-case SI delta

2. **具体流程**：
 - `set_analysis_mode -si`
 - `read_parasitics -keep_capacitive_coupling`
 - `update_timing -full`
 - `report_timing -delay min/max`

3. **关键参数**：
 - `aggressor_exclusion`：把弱耦合的 aggressor 排除
 - `filter_acceleration_slack`：跳过 slack > 阈值的 net（加速）

**加分点**：
- 提到 "实际生产中会用 AOCV/POCV 进一步叠加 SI 概率分布"
- 提到 "noise glitch 是 setup 检查外的额外项——单独跑 noise analysis"

### 题 4：Glitch 是什么？什么情况下需要担心？

**参考答案**：

**Glitch**（毛刺）：一根静态线（victim）因为邻线（aggressor）翻转，**通过耦合电容注入电荷**，导致 victim 上出现一个不希望的脉冲。

**两类 Glitch**：

| 类型 | 触发条件 | 持续时间 | 影响 |
|---|---|---|---|
| **Over-shoot** | aggressor 上升沿 | 几十 ps | 不会 latch，但动态功耗增加 |
| **Under-shoot** | aggressor 下降沿 | 几十 ps | 同上 |

**真的会出错的情况**：
- Glitch 宽度 > 后级 latch 的 setup-hold window
- 异步 reset / enable 信号被 glitch
- Memory write enable 被 glitch → 写入错误数据

**检测**：
- `report_noise` 或 `report_noise_calculation`
- 看 noise slack（与 glitch 容限的差值）

**修复**：
- 加大 victim 驱动（增加 Cg，Cc 比例下降）
- 减小 victim 平行长度
- Shielding

**加分点**：
- 提到 "Glitch 在低功耗设计里特别关键——reduced swing cell 容易受 glitch"
- 提到 "现代综合工具会做 noise-aware synthesis"

### 题 5：Shielding 怎么做？什么场景下必须做？

**参考答案**：

**三种方式**：

```
方式 1: 全程共模 Shielding（最稳）
┌─────────────┐
│ VSS │ Signal │ VSS │ Signal │ VSS │
└─────────────┘
代价：占 2x 走线资源

方式 2: Co-shielding 标记
工具自动把指定 net（shield_nets）插入到攻击线之间
代价：中等

方式 3: Spare cell / Power Strap
在 cross-over 点加 VDD/VSS 短接
代价：最小，但保护不完整
```

**需要 Shielding 的场景**（注意：时钟网络的**常规**手法是 NDR——加倍宽度与间距、优先走高层；只有在 SI 实测超标或对抖动要求极苛刻时才补 shield，全线屏蔽会吃掉大量绕线资源并增加负载电容）：

1. **极敏感的 Clock Net**（实测 SI 超标后补做）
2. **Reset / Async Set**：异步信号被 glitch 后果严重
3. **Scan Chain**：DFT 信号完整性要求
4. **Memory Interface**：SRAM 读写使能/地址
5. **跨长距离的敏感信号**（如 JTAG）

**加分点**：
- 提到 "Shielding 也会引入额外电容（load 上升）"
- 提到 "7nm 工艺 cross-talk noise 容限收窄，越来越多 critical net 要 shield"
- 提到 "Innovus 里 `setShield` / `setShieldNet` 命令"

### 题 6：什么是 Aggressor Window？什么情况下会有多个 Aggressor？

**参考答案**：

**Aggressor Window** = 在 victim 翻转的**敏感时间窗**内翻转的 aggressor net，对 victim 才有影响。

**敏感窗范围**：
```
[-1.5 × victim_delay, +1.5 × victim_delay]
```

**多 Aggressor 场景**：

```
 victim:  ──────┐
              │← toggle 时刻
 aggressor 1: ──┐  
             └── 在窗口内 → 算 aggressor
 aggressor 2: ─────┐
                └── 在窗口外 → 不算
 aggressor 3: ───┐
              └── 在窗口内 → 算
```

**多 Aggressor 影响**：
- 1 个 aggressor：1x Cc 影响
- 2 个同向：2x Cc 影响（叠加）
- 2 个反向：可抵消（部分）

**工具简化**：
- `set_aggressor_window` 设置窗口
- 静态分析时只考虑窗口内的

**加分点**：
- 提到 "实际多 aggressor 用 CCS / ECSM noise 模型仿真"
- 提到 "PrimeTime-SI 自动算 window，但默认是 conservative"
- 提到 "modern AOCV/POCV 把 SI 视为概率事件，多 aggressor 用概率叠加"

### 题 7：先进工艺下 SI 有什么新挑战？

**参考答案**：

| 挑战 | 原因 | 应对 |
|---|---|---|
| **强耦合**（Kc > 0.4）| 间距缩小、宽度增加 | spacing 解决不了，shielding 普遍化 |
| **3D 结构**（FinFET）| 垂直 fin 增大 Cc | 仿真模型更复杂 |
| **Wire Resistance 上升** | Cu 电阻 + 尺寸缩小 | RC 延迟占比上升 |
| **多层堆叠** | 12+ 金属层 | 跨层耦合显著 |
| **Dishing / Erosion** | CMP 不均 | 局部 R 差异大 |
| **Electromigration 反向影响** | 高电流导致线变形 | 走线寿命评估 |

**7nm/5nm 的关键变化**：
- 同层间距缩小，**Kc 上升 30%~50%**
- 必须用 shield 或 differential routing
- SI 在总 delay 中占比 **> 30%**

**加分点**：
- 提到 "FinFET 的 fin 高度增加，垂直 Cc 大幅上升"
- 提到 "3nm 工艺开始用 GAA（Gate-All-Around），耦合特性又变"
- 提到 "SI 不再是后端问题——综合阶段就要 noise-aware"

### 题 8：什么是 Noise Margin？怎么分析？

**参考答案**：

**Noise Margin**（噪声容限）：cell 输入端能承受的最大不破坏逻辑的干扰幅度。

```
Noise Margin = (Driver_Cg / (Driver_Cg + Aggressor_Cc)) × VDD
```

**两类**：

| 类型 | 含义 |
|---|---|
| **DC Noise Margin** | 静态情况下的容限 |
| **AC Noise Margin** | 动态情况下（与 pulse width 相关）|

**AC 噪声曲线**（cell 库提供）：
- 噪声 pulse 越宽 → 容限越低
- 噪声 pulse 越窄 → 容限越高（cell 不响应）

**分析流程**：
1. `report_noise_calculation` → 列出所有 victim 的 noise
2. 找 noise pulse 宽度 + 幅度
3. 对比 cell 的 noise immunity curve
4. noise > margin → 违例

**修复**：
- 加大 victim 驱动
- 减小 aggressor 驱动
- shielding
- 减小 Cc

**加分点**：
- 提到 "HVT cell 噪声容限低（驱动弱）"
- 提到 "low-Vt cell 对 noise 敏感"
- 提到 "综合阶段就要 noise-aware，否则后期 fix 代价大"

### 题 9：什么是 Delay Change？Setup 和 Hold 受影响机制？

**参考答案**：

**Delay Change**：考虑串扰前后 cell delay 的差异。

```
Delay_with_SI = Delay_isolated + SI_Delta
```

**两种情况**：

| Aggressor 翻转方向 | 注入电荷方向 | Delay 变化 | 影响 |
|---|---|---|---|
| **同向**（0→0→1 与 victim 0→1）| 加速 victim 充放电 | **变短** | **Hold 变难** |
| **反向**（0→0→1 与 victim 1→0）| 抵消 victim 充放电 | **变长** | **Setup 变难** |

**关键洞察**：
- 串扰**总是让 worst case 更坏**（setup + hold 都可能出问题）
- 同一根 net 在 setup 和 hold 中可能受不同方向 aggressor 影响

**修复策略**：

| 违例类型 | 修复 |
|---|---|
| Setup 违例（delay 变长）| 加大 driver, shield, 减小 Cc |
| Hold 违例（delay 变短）| 加 buffer 增加 delay, 或 disable SI on this path |

**加分点**：
- 提到 "Hold 违例在 SI 下变得普遍——以前可忽略，现在必查"
- 提到 "disable SI 是最后手段——必须 verify 真的不再 critical"
- 提到 "CCS noise model 比 ECSM 更准，是 sign-off 必用"

### 题 10：CCS / ECSM 是什么？为什么先进工艺必须用？

**参考答案**：

| 模型 | 全称 | 时代 | 精度 |
|---|---|---|---|
| **NLDM** | Non-Linear Delay Model | 90nm 以上 | 不含 SI |
| **ECSM** | Effective Current Source Model（Cadence 系） | 65nm 起 | 电流源模型，含部分 SI |
| **CCS** | Composite Current Source（Synopsys 系） | 28nm 及以下 | 完整 SI + noise |

ECSM 与 CCS 是并列的两大电流源模型体系，不是时代递进关系——用哪套取决于你的签核工具链和库支持。
| **CCS Noise** | CCS + Noise | 7nm 及以下 | SI + glitch 联合 |

**为什么先进工艺必须用？**
- 7nm 工艺 Kc > 0.4，NLDM 完全不准确
- 必须用 CCS 仿真电流波形
- 同时考虑 waveform shape 对 delay 的影响

**实际使用**：
- 综合：必须用 CCS 库（综合工具会做 noise-aware）
- STA：PrimeTime / Tempus 选 CCS 模型
- PV：用 CCS 模型提取 delay

**加分点**：
- 提到 "CCS vs CCS Noise 区别：CCS Noise 多了 glitch 计算"
- 提到 "5nm 工艺的 cell 库必须支持 CCS Noise"
- 提到 "有的先进工艺库同时提供 ECSM 和 CCS——sign-off 用 CCS，综合可用 ECSM"

## 三、综合题（开放题）

### 题 11：项目里遇到严重的 SI 问题（setup 违例），你怎么 debug？

**参考答案框架**：

1. **确认 SI 是真因**：
 - `report_timing -delay max` 看 setup
 - 用 `set_analysis_mode -si` 切换
 - 对比"with SI"和"without SI"的 slack

2. **定位受害 net**：
 - `report_noise` 看哪条线 noise 大
 - `report_timing -delay max -crosstalk` 看 SI delta

3. **分析原因**：
 - 是不是 parallel 长度太长
 - 是不是和 clock 平行（最严重）
 - 是不是和 reset/control 平行

4. **修复策略**（成本由低到高）：
 - 加大 victim driver（增加 Cg）
 - 减小 aggressor driver
 - shielding 关键 net
 - 改 routing（减少平行长度）

5. **验证**：
 - 重跑 STA
 - 确认无回归
 - 检查 hold 也没变差

**加分点**：
- 提到 "修 SI 同时要看 hold——可能原本不 critical 的 net 因为 SI 变 critical"
- 提到 "clock net 的常规手法是 NDR（2W2S/3W3S）+ 走高层，shield 只在极少数对抖动要求苛刻的时钟上做——默认全线屏蔽会吃掉绕线资源并加大负载电容"
- 提到 "实际工作中 SI 修复是 iterative 的——一次修不完"

## 四、面试常见追问

| 追问 | 应对 |
|---|---|
| "SI 修复只能 shield 吗？" | "不，driver sizing、layer assignment、改 routing 都可以" |
| "Kc 多大算严重？" | "7nm Kc > 0.4 算严重，5nm Kc > 0.5 算严重" |
| "NLDM 模型不能用吗？" | "28nm 以上勉强能用，7nm 必须 CCS" |
| "Glitch 会 latch 错误吗？" | "理论上不会，但实际可能——必须看 noise margin" |
| "SI 是 PVT 变化吗？" | "不是。PVT 是 process/voltage/temperature，SI 是几何耦合" |

## 五、面试避坑

1. 说 "SI 只是线越近越严重"——实际**平行长度、攻击线数、电压摆幅**都有关
2. 漏提 Hold 违例——SI 对 hold 影响比 setup 更隐蔽但同样严重
3. 不知道 CCS / NLDM 区别——7nm 以下必考
4. 把 Glitch 和 Delay Change 混为一谈——**两者机制不同、影响不同**
5. 以为 Shield 是万能解——Shield 也会引入 load
