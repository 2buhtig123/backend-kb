# 手撕计算题：Setup/Hold、功耗、IR Drop 与面积的估算法

后端岗的笔面试里有一类题是不看你背了多少，只看你算得对不对。这类题的好处是它有标准答案，坏处是现场紧张起来容易把符号弄反。

这篇把最常考的六类计算从头推一遍：每一类给公式、给例题、给完整答案，以及一些容易记混的方向性问题。

> 提醒：面试时不要直接写答案。**先说你的假设**（比如"假定这里不计 CPPR""假定 clock uncertainty 单独给出"），再代数字。面试官想看的是你怎么组织已知条件，而不是你会不会按计算器。

## 一、Setup / Hold 时序手算

这是出场率最高的一类题。

### 1.1 基本公式

设两个触发器 FF1（发射）和 FF2（捕获），中间是组合逻辑：

```
数据到达时间（Arrival Time）：
    AT = T_launch + T_ck_q + T_logic

数据要求时间（Required Time，setup 检查）：
    RT = T_capture + T_period - T_setup

Setup Slack：
    Slack_setup = RT - AT
                = (T_capture - T_launch) + T_period - T_setup - T_ck_q - T_logic
```

其中 `(T_capture - T_launch)` 就是 clock skew。展开写更直观：

```
Slack_setup = T_period + T_skew - T_setup - T_ck_q - T_logic
```

如果还要计入 clock uncertainty（含 jitter 与额外 margin），惯用表达式是：

```
Slack_setup = T_period + T_skew - T_setup - T_ck_q - T_logic - T_uncertainty - T_cppt_adj
```

Setup 检查的是**发射沿 vs 其后的那个捕获沿**（相隔 1 个周期）；Hold 检查的是**发射沿 vs 同一时刻的捕获沿**（捕获沿就是发射沿本身，不是之后的那个沿），所以周期不进入 Hold 公式：

```
数据到达时间（最早）：
    AT_min = T_launch(min) + T_ck_q(min) + T_logic(min)

数据要求时间：
    RT_hold = T_capture(max) + T_hold

Hold Slack：
    Slack_hold = AT_min - RT_hold
               = T_ck_q(min) + T_logic(min) - T_hold - (T_capture - T_launch)
```

**方向性记法**（最容易翻车的地方）：

| 项目 | 越大越好还是越小越好 | 为什么 |
|---|---|---|
| T_period | 越大 setup 越松 | 周期变长，数据有更多时间到达 |
| T_skew（capture 晚到 launch） | 对 setup 有利、对 hold 有害 | capture 时钟晚到，等于多给数据时间 |
| T_uncertainty | 越大越严 | 它会被从周期里扣掉 |
| T_logic | 越大越严 | 占用周期的可用时间 |
| T_hold | 越大 hold 越难 | 需要数据保持更久 |

### 1.2 例题

**题目**：时钟周期 2ns，launch 时钟到达时间 0.3ns，capture 时钟到达时间 0.36ns，触发器 T_ck_q = 0.08ns，T_setup = 0.05ns，组合逻辑延迟 1.42ns，clock uncertainty = 0.05ns。求 setup slack。

**解**：

```
T_skew = 0.36 - 0.30 = 0.06 ns

Slack = T_period + T_skew - T_setup - T_ck_q - T_logic - T_uncertainty
      = 2.00 + 0.06 - 0.05 - 0.08 - 1.42 - 0.05
      = 0.46 ns
```

结论：setup slack 为正 0.46ns，收敛。

**追问**：如果去掉 uncertainty，slack 变成 0.51ns，这说明 uncertainty 吃掉了 50ps 的余量。面试官如果接着问"uncertainty 里含什么"，回答见《面试追问 Top 30》的第 4 条。

### 1.3 例题：hold 检查

**题目**：接上题。已知 T_ck_q(min) = 0.05ns，T_logic(min) = 0.12ns，T_hold = 0.06ns，clock skew 同上为 0.06ns。求 hold slack。

**解**：

```
Slack_hold = T_ck_q(min) + T_logic(min) - T_hold - T_skew
           = 0.05 + 0.12 - 0.06 - 0.06
           = 0.05 ns
```

结论：hold slack = 0.05ns，满足但余量很薄。这就是为什么 hold 修复一般要留一定正 margin（工具里通常设 `opt_hold_target_slack` 略大于 0）。

**注意 skew 的符号**：这里 skew 是减项。如果 clock tree 反过来（capture 时钟比 launch 早到），skew 为负，那这一项反而变成加项。

## 二、最高工作频率估算

这类题有两种问法，都常见。

### 2.1 已知各段延迟，求 Fmax

```
T_period(min) = T_ck_q + T_logic(max) + T_setup + T_uncertainty - T_skew(有利时)

Fmax = 1 / T_period(min)
```

**例题**：T_ck_q = 0.10ns，T_logic = 1.20ns，T_setup = 0.06ns，uncertainty = 0.08ns，skew 忽略。

```
T_period(min) = 0.10 + 1.20 + 0.06 + 0.08 = 1.44 ns
Fmax = 1 / 1.44 ns ≈ 694 MHz
```

### 2.2 已知目标频率，反推允许的组合逻辑级数

这类题考的是「数量级感」。用 FO4（Fanout-of-4 inverter delay）做估算单位最方便：

| 工艺节点 | FO4 延迟量级 |
|---|---|
| 28nm | 约 20-30 ps |
| 14/16nm | 约 15-20 ps |
| 7nm | 约 10-15 ps |

**例题**：目标频率 1GHz（周期 1ns），扣除 T_ck_q 0.1ns、T_setup 0.06ns、uncertainty 0.08ns 后，剩给组合逻辑的时间约 0.76ns。工艺为 28nm（取 FO4 = 25ps）。这条路径最多能经过多少级 2 输入 NAND（NAND2 的延迟约等于 1 个 FO4）？

```
可用逻辑时间 = 1.00 - 0.10 - 0.06 - 0.08 = 0.76 ns
级数 ≈ 0.76 / 0.025 ≈ 30 级
```

结论：大约 30 级逻辑。这是个量级判断，实际还要扣 net delay（在先进节点里 net delay 常常占一半以上），所以经验数字会更少。

**面试加分点**：提一句"这里还要考虑 net delay 占比，实际路径通常 cell delay 与 net delay 各占一半左右"，说明你知道实际收敛时不是只算 cell。

## 三、动态功耗估算

### 3.1 核心公式

```
P_dynamic = α · C_load · V² · f
```

| 符号 | 含义 | 常见取值来源 |
|---|---|---|
| α | 活动因子（每个周期翻转概率） | 假设值 0.1-0.2，或由 SAIF/VCD 给出 |
| C_load | 负载电容 | 由寄生提取给出；手算时用单位长度电容 × 线长 |
| V | 电源电压 | 0.9V / 0.75V / 1.8V 视节点而定 |
| f | 时钟频率 | 由 clock spec 决定 |

### 3.2 例题

**题目**：某模块总负载电容估计 200pF，电源电压 0.9V，工作频率 1GHz，平均活动因子 0.15。求动态功耗。

**解**：

```
P = 0.15 × 200e-12 × (0.9)² × 1e9
  = 0.15 × 200e-12 × 0.81 × 1e9
  = 0.15 × 0.162
  = 0.0243 W = 24.3 mW
```

### 3.3 追问：电压降 10%，功耗降多少？

```
P ∝ V²  →  (0.9V → 0.81V) 即 V 降 10%
P_new / P_old = (0.81/0.90)² = 0.81
```

降约 19%。这是"降低功耗最有效的手段是降电压"这句话的来源。

**但要注意**：降 V 会让单元延迟变大，时序变差，所以实际要做 DVFS：性能要求高的档位用高电压，空闲时用低电压。面试官如果问"那为什么不直接降到最低电压"，这是在看你有没有意识到电压-延迟的权衡。

## 四、IR Drop 估算

面试里这类题通常给你几何参数，让你算一段电源线的电阻，再乘电流。

### 4.1 金属线电阻

```
R = R_sheet · (L / W)
```

`R_sheet` 是方块电阻（单位 Ω/sq），`L/W` 是方块数。顶层金属厚，R_sheet 小（典型 0.02-0.05 Ω/sq）；下层金属薄，R_sheet 大（可能 0.1 Ω/sq 甚至更高）。

**例题**：顶层 metal 的方块电阻为 0.04 Ω/sq，一段长 800μm、宽 4μm 的电源走线，其电阻是多少？

```
方块数 = 800 / 4 = 200 sq
R = 0.04 × 200 = 8 Ω
```

### 4.2 压降估算

**例题（续）**：这条支路上流过的电流为 20mA，求这条线上的直流压降。

```
ΔV = I · R = 20e-3 × 8 = 0.16 V = 160 mV
```

**结论与分析**：如果电源是 0.9V，允许压降通常是 5%-10%（即 45-90mV），那么 160mV 已经严重超标，需要加宽 strap 或加密 strap。

加宽一倍 → 方块数减半 → 电阻减半 → 压降减半（80mV）。加密一倍 → 每段支路的电流减半 → 压降减半。**加密 strap 与加宽 strap 效果在这里是等价的**，但实际选择要看占用面积与拥塞。

### 4.3 电流密度的限制

另一个常考角度：给定某层金属的最大允许电流密度上限（如 J_max = 1 mA/μm），算某宽度能否承载某电流。

**例题**：某层 metal 的 EM 限流规格是 1 mA/μm，一条 2μm 宽的线需要承载 3mA 电流，是否安全？

```
该线允许最大电流 = 1 mA/μm × 2μm = 2 mA < 3 mA
```

不安全。这就是 Electromigration 检查（EM check）的基本形式，也是为什么电源 strap 都要按模具宽度设置并接受 EM 检查。

## 五、面积与实例数估算

### 5.1 基本换算

```
Core Area = Core Width × Core Height
Standard Cell Area = Core Area × Utilization
Instance Count ≈ Standard Cell Area / Average Cell Area
```

注意单位换算：**1 mm² = 10⁶ μm²**。

### 5.2 例题

**题目**：某设计 core 尺寸 2.0mm × 2.0mm，utilization 设定为 70%，28nm 工艺下标准单元的平均面积约 1.4 μm²。估算实例数。

**解**：

```
Core Area = 2.0 × 2.0 = 4.0 mm² = 4.0e6 μm²
Standard Cell Area = 4.0e6 × 0.70 = 2.8e6 μm²
Instance Count ≈ 2.8e6 / 1.4 ≈ 2.0e6  → 约 200 万实例
```

### 5.3 反过来：已知实例数估算面积

**题目**：设计规模约 50 万实例，平均单元面积 2.0 μm²，utilization 目标 65%。估算 core 面积应为多少。

```
Standard Cell Area = 5e5 × 2.0 = 1.0e6 μm² = 1.0 mm²
Core Area = 1.0 / 0.65 ≈ 1.54 mm²
```

方形下约为 1.24mm × 1.24mm。

**面试加分点**：实际 core 尺寸还要加 IO ring / pad ring / scribe line，且 shape 不一定取正方形（需要考虑 macro 摆放、aspect ratio 对绕线的影响）。提一句这个，说明你做过真实的 floorplan。

### 5.4 macro 占比估算

```
Macro Area Ratio = Σ(Macro Area) / Core Area
```

经验值：macro 占用超过 50%-60% 时，floorplan 会很吃力——标准单元区域被压缩、congestion 容易恶化。这也是为什么 SRAM 集成类题目常问"macro 怎么摆"（详见《SRAM / Macro 集成》篇）。

## 六、绕线延迟估算

最后一类，考的是对寄生参数的量级感。

### 6.1 线电容

```
C_wire = C_per_unit_length × L
```

28nm 下中层金属的 total capacitance（含 fringing）大约 0.2 fF/μm 量级。

**例题**：一条长 200μm 的信号线，单位长度电容 0.2 fF/μm，总电容是多少？

```
C = 0.2 fF/μm × 200 μm = 40 fF = 40e-15 F
```

这个量级是对的：一个单位 Fanout 负载大概几 fF 到几十 fF。

### 6.2 线延迟

一条分布 RC 线的 Elmore 延迟约为：

```
t_delay ≈ 0.5 × R_total × C_total     （简单估算）
```

**例题（续）**：该线宽 0.1μm，方块电阻 0.1 Ω/sq。

```
方块数 = 200 / 0.1 = 2000 sq
R_total = 0.1 × 2000 = 200 Ω
C_total = 40 fF = 40e-15 F
t_delay ≈ 0.5 × 200 × 40e-15 = 4e-12 s = 4 ps
```

看起来不大，但如果这条线在关键路径上占了好几个这样长度，累积起来的 net delay 就会接近百 ps 量级——这和一份 28nm 设计里典型 net delay 占总 delay 的比例是一致的。

**面试加分点**：从这里引申出为什么先进节点要用 repeater/buffer insertion：长线延迟随长度近似平方增长（R∝L，C∝L），所以插入 buffer 把长线切成几段，总延迟线性叠加反而比一整根更快。

## 单位换算速查表

| 量 | 换算 |
|---|---|
| 长度 | 1 mm = 1000 μm = 10⁶ nm |
| 面积 | 1 mm² = 10⁶ μm² |
| 时间 | 1 ns = 1000 ps；1 ps = 1000 fs |
| 电容 | 1 pF = 1000 fF = 10⁻¹² F |
| 频率/周期 | f = 1 / T；1 GHz 对应周期 1 ns |
| 功耗 | P = αCV²f（单位：W = F × V² × Hz） |

## 面试五问

1. **公式记反了怎么办？** 用一个 keep-safe 检查：周期变大，setup 一定会变好，所以 T_period 在 setup 公式里必须是加项；同理不确定性越大越严，必须是减项。按这个方向性验一遍公式，比硬背靠谱。

2. **计算题要不要考虑 CPPR / derate？** 先假设不考虑，把基础版算出来，然后主动说一句"实际 sign-off 里还要减去 CPPR 和 AOCV/POCV 的悲观量，所以真实 slack 会更小一些"——这句话往往直接加分。

3. **面试官给的数字明显不合理（比如 skew 比周期还大）怎么办？** 先指出不合理，再按他给的数字算。直接说"这个 skew 相对周期太大了，正常应该只在几十 ps"，说明你有工程判断力。

4. **估算类题目（如"这条路径大概多少级逻辑"）没有唯一答案怎么办？** 面试官要的是量级和方法，不是精确值。把你的假设（FO4 取多少、net delay 占比取多少）说清楚，给出计算过程，量级对了就得分。

5. **这类题要练多少？** 五道左右：setup 一道、hold 一道、Fmax 一道、功耗一道、IR Drop 一道。真正掌握了之后其他的都是同一个骨架换数字。现场最大的敌人是单位换算错（pF vs fF、mm² vs μm²），把上面的换算表单独背熟比刷题更划算。

## 小结

六类题的计算骨架其实只有三条：

1. **时序类**：把 arrival 时间和 required 时间分别写清楚，再相减。所有 setup/hold 题都是这个形式，区别只在于要不要加 skew、uncertainty、CPPR。
2. **功耗 / 电源类**：`P = αCV²f` 与 `ΔV = IR`。注意 V 的平方关系和 R 的 `L/W` 形式（这个几何关系是面试高频考点）。
3. **面积 / 绕线类**：单位换算 + utilization 定义。精度要求不高，但单位必须准。

现场答题的三条纪律：**先说假设、分步列式、量级复核**。做到这三点，即使某一问算错了，面试官也能看到你的思路是对的。

到这里求职实战模块的三篇就齐了：《简历怎么写》解决"进场资格"，《追问 Top 30》解决"扛不扛得住口语追问"，这篇解决"提笔算不算得出来"。下一步如果要继续加深，方向上最有价值的两个是**时钟门控与 Clock Gating 策略**（时序/功耗/DFT 三者的交汇点）和**Tcl 进阶脚本**，这两块既是技术深水区，也是面试出题的高频区。
