本篇为《数字集成电路物理设计》第 6 章（p.140-168）的浓缩笔记，可与原书对照阅读。原书 6.1 是延迟计算与布线参数提取，6.2 是寄生参数与延迟格式文件，6.3 是静态时序分析，6.4 是时序优化，6.5 是总结。本文沿用原书编号。

完成布线后一项最重要、最必需的工作是做静态时序分析；结果出现时序违例，就要对物理设计进行优化。分析前首先要对芯片物理版图做电阻、电感（以及互感）、电容参数（RLC）提取，再做延时计算（p.140）。除模拟和射频设计外，多数数字电路只关心电阻和电容，不考虑电感时习惯称为 RC 提取（p.140）。用 SPICE 网表和工艺器件模型从版图提取 RC 值，可以算出单元间有逻辑关系的端口到端口延迟、各端口电容和 setup、hold 时序特征，因此 RC 提取与延时计算是 STA 的前期工作（p.140）。

延时由器件延时和互连延时构成。器件延时在时序库标定（library characterization）时已算出，分析时主要关心互连 RC 提取与延时计算（p.140）。亚微米时两层互连相距较远，提取可忽略底层单元；DSM 后两层靠得近，要做“在逻辑单元上”（OTC，over the cell）的“门级”提取；纳米设计中底层单元的晶体管级版图影响更大（p.140）。互连从四层铝到八层铜，层间寄生更复杂，提取时间随之增长（p.140）。

## 6.1 延迟计算与布线参数提取

### 6.1.1 延迟计算模型

RC 提取可在布局后或时钟树综合后进行，但此时布线尚未完成，只能用很不准确甚至错误的 WLM 估算。经典逻辑综合的时序优化依赖时序库给出的 WLM（也称 statistical WLM，SWLM），或用校正过的定制 WLM（customer WLM，CWLM）做 RC 估算；这些估计只能用于早期分析，只有布线结束后互连的物理特性确定，RC 提取才是真实的（p.141）。WLM 于 1985 年开始应用，流程是综合后的门级网表直接布局布线；后来当时序收敛困难时，人们用物理综合完成最终布线后再产生新的 CWLM 取代 SWLM，并重复布局布线过程（p.141-142）。图 6-4 中 T2 读入 SWLM、T8 产生 CWLM（p.142）。

互连 RC 网络可简化为“集总式”（lumped）模型，有 L 形、T 形和 Π 形（π 形）三种（p.142，图 6-5）。简化为单个电阻和单个电容的 L 形网络，集总延迟 `t_p ≈ 0.693RC`（式 2-3），结果较悲观且不准确，适合较短的互连线；T 形准确度稍有提高；π 形网络实际上是 Elmore 延时模型的一级近似（p.142）。

将 T 形网络扩展为 n 个节点可得 RC 分布式网络（图 6-6）。流过节点 j 的电流满足（p.142）：

`C dV_j/dt = (I_j-1 - I_j) = (V_j-1 - V_j)/R - (V_j - V_j+1)/R`（6-1）

设 r、c 为单位长度 Δl 的电阻和电容，l 为总线长，R = rΔl、C = cΔl，按 KCL 列方程可得扩散方程（p.143）：

`rc ∂V/∂t = ∂²V/∂x²`（6-2）

其近似解为（p.143）：

`τ(V_out) = rc(Δl)²[n(n+1)/2]`（6-3）

式中 n 为节点数，n = l/Δl；n 趋于无穷、Δl 趋于无穷小时，分布式模型的准确度随 n 增大而提高（p.143）。线很长时按 Elmore 延迟，式（6-3）近似为（p.143）：

`τ(V_out) ≈ rc l²/2 = R_wire C_wire/2`（6-4）

已假定每段 r、c 相等，则 R_wire = rl、C_wire = cl。实验发现 50% V_DD 时总 RC 延迟为 0.38R_wire C_wire，比式（6-4）的 0.5R_wire C_wire 小（p.143）。

扇出为 1 时，单条 RC 链中任意节点 N 有（p.143）：

`τ_N = Σ R_i→N C_i = Σ C_i Σ R_j`（6-5）

即先对每个节点算出（R1+R2+…+Ri）Ci，再把输入到节点 N 的所有单项相加。三级 RC 链为 `τ3 = R1C1 + (R1+R2)C2 + (R1+R2+R3)C3`（p.143）。扇出大于 1 时称 RC 树，任意节点 i 的 Elmore 延迟为（p.143）：

`τ_i = Σ (R_ik × C_k)`，k = 1…N（6-6）

式中 N 为节点数，C_k 为节点 k 的电容，R_ik 为输入到节点 k 的公共路径电阻（p.144）。

为更精确处理长线中 π 模型的过高估计，DSM 设计开始采用 Darty-Pileggi 的动态等效 Thevenin 电路（p.144）。若时钟树插入 N 个缓冲器，线延迟为

`τ = RC(Δl)²/(2(N+1)) + N t_buffer`

驱动器门延迟较小（0.18μm 下约 0.2ns），整个时钟网络的总延迟会小很多（p.144）。

### 6.1.2 电阻参数提取

电阻提取把连线按线宽分割成小方块，以每方块（per square，1/□）为单位，再把长线分段（考虑存储与计算速度），按欧姆定律求总电阻（p.144，图 6-7）：

`R_wire = ρ l/(W t) = R_sheet l/W`（6-7）

式中 l、W、t 为长、宽、厚，ρ 为电阻率；R_sheet = ρ/t 为截面电阻，适用于每层平面形状（p.144）。通孔电阻由晶圆代工厂直接给出。图 6-8 的模型为 (a) 以小方块为单位、(b) 分段表示、(c) 分段法提高速度与准确度（p.144-145）。

建库时已讨论 PTV，建立时序库或做 RC 分析至少要用 3 种工艺温度电压条件。不同温度 T 下（p.144）：

`R_T = R_T0 × [1 + α(T - T0)]`（6-8）

T、T0 为导体温度和室温，α 为温度系数（1/℃）。室温 20℃ 时 α_Cu = 4.041×10⁻³、α_Al = 4.308×10⁻³；任意导体的温度系数为（p.145）：

`α = (1/R_T) × dR/dT × 100 (%/℃)`（6-9）

纳米工艺中 CMP 对寄生参数影响更大：铜互连的 Damascene 工艺要加插入介电层（ILD），防铜扩散还要加薄层钽（Ta）作封装（cladding），钽电阻率高，对 R、C 提取都有影响（p.145）。光刻的线边缘增大（WEE，wire edge enlargement）使电阻减小需校正；CMP 产生盘状凹陷，可用分裂法（splitting）把宽线分成多个窄条改进（p.145-146）。

### 6.1.3 电容参数提取

单位长度总电容由面积电容 C_A、侧面电容 C_L、边缘电容 C_F 三部分组成（图 6-10），即（p.146）：

`C_wire = C_A + C_L + C_F`（6-10）

若互连线正好位于另两条线中间，各项乘以 2（p.146）。三者分别为（p.146）：

`C_A = ε_ox · W/H`（6-10a）

`C_L = ε_ox · T/S`（6-10b）

`C_F = ε_ox · ln(1 + T/H)`（6-10c）

W、H 为线宽和对地高度，T、S 为金属厚度和相邻金属侧面间隔；ε_ox = ε_r·ε_0，ε_r(SiO2) = 3.97（p.146）。0.8μm 三层金属的参数见表 6-1：H 为 1.46/3.29/5.34μm，T 为 0.63/0.85/0.85μm，W 均为 0.80μm（p.146）。

亚微米设计中互连线相距较远、t ≪ S 时可忽略 C_L，用平行板模型计算长度为 L 的电容（p.146）：

`C_wire = L·W·C_A + 2·(L+W)·C_F`（6-11a）

面积电容常用 C_2 表示。工艺节点大于 0.25μm、W/H ≤ 1 时，可用 VDMF 模型（p.146-147）：

`C_wire(VDMF) = ε_ox { (W/H) + 0.77 + 1.06(W/H)^0.25 + 1.06(T/H)^0.25 }`（6-11b）

0.25~0.18μm 需要二维（2D）或准三维（2.5D）模型（图 6-11）；互连从 2~3 层增到 4~6 层、再到 7~9 层（130nm 以下）后，要用 3D 计算，130nm 三层金属的参数见表 6-2（p.147）。

三维模型中空间电荷的几率分布用格林函数表示（p.147）：

`p = G(y, x, τ)`（6-12）

格林函数是未知概率函数，可用蒙特卡罗方法求解；Le Coz 等于 1991 年在 2D 提取中用随机行走（random walk）取样使函数尽早收敛，后来有 FastCap、QuickCap 等 3D 算法，通称现场解决方案（field solver）（p.147-148）。3D 结果用 Maxwell 电容矩阵表示，更精确的求解用泊松方程、拉普拉斯方程或速矢法，典型应用是边界元素方法（HBBEM）（p.148）。

### 6.1.4 电感参数提取

深亚微米后分布参数的重点从电阻变为电容，纳米节点电感开始成为问题重点（p.148）。由 Φ = L·i 求导得 ΔV = L·(di/dt)，直流时 ΔV 为零；高频下电流变化率很大，封装连接点和电源分配系统中的电感效应不可忽略（p.148）。RC 网络实际应是 RLC 网络（图 6-13），单位长度电感为（p.148）：

`L_wire = ε_ox · μ_ox / C_wire`（6-13）

μ_ox 为磁导率，μ_0 = 12.6×10⁻⁷ Wb/A（p.148）。完整提取包括 R、C、L、K（互感）；除 CPU 中的高频设计外，大部分低频数字设计不考虑 L 和 K（p.148）。

## 6.2 寄生参数与延迟格式文件

### 6.2.1 寄生参数格式 SPF 文件

RC 提取结果用标准寄生参数格式（SPF）文件表示。书中的原话是“目前在工程中使用的 SPF 有三种形式，分别是 DSPF、RSPF 和 SPEF”（p.149）。这里要说明：三者是并列的文件格式，不是三种精度等级，SPEF 也不是按 D、R、P 分级的格式。

最早的标准寄生参数格式（SPF）为 RC 格式，1990 年制定；后来用 SPICE 格式以 DSPF 或 RSPF 表示，再加上后来发展的 SPEF，共 4 种主要格式（p.149）：

1. SPF——Standard Parasitic Format，标准寄生参数格式。
2. DSPF——Detailed Standard Parasitic Format，详细标准寄生参数格式。
3. RSPF——Reduced Standard Parasitic Format，简化标准寄生参数格式。
4. SPEF——Standard Parasitic Exchange Format，标准寄生参数交换格式。

不同的 SPF 都是对网络中的 RC 进行记录（图 6-14）。DSPF 分两大部分：文件基本属性和详细的 RC 寄生参数；RSPF 把连线寄生信息等效为驱动与负载的关系模型，代替 DSPF 的详细寄生，用有效负载模型和线延迟模型两个模型表示（p.149）。也就是说，DSPF 记录每段线的 R、C 明细，RSPF 只给驱动器看到的等效负载和线延迟模型，文件更小但丢掉了线内分布信息（p.149）。

SPEF 与 DSPF 相似，1998 年制定为 IEEE 标准 1481，增添了电感 L 并包含信号转换时间（slew），应用更广；它还建立了延迟计算语言（DCL）传递时序和功耗参数，配合延迟功耗计算系统（DPCS）使用（p.149-150）。版本演进为 SPF/DSPF/RSPF 1.0~1.5 版（1990~1997，Cadence）、SPEF/DCS（1996，OVI）和 IEEE 1481（1999）（p.150）。

### 6.2.2 标准延迟格式 SDF 文件

SPF 是中间信息文件，做时序分析和优化前要先做延迟计算，结果用标准延迟格式（SDF）文件表示（p.150）。按 3 种端角（corner）可获得 3 个 SPF 和 3 个 SDF；SDF 的 3 组数据为最佳（best/最快 fast）、典型（typical/正常 normal）、最差（worst/最慢 slow），STA 时分别选用（p.150，图 6-16）。

### 6.2.3 SDF 文件的应用

工程中可提取寄生参数直接算出 SDF，也可分别读入 SPF 或 SDF；SDF 为不同 EDA 工具提供一致数据，同一设计允许每个模块有自己的 SDF（p.150）。SDF 是布线后设计状态的延时报告，最广泛的应用是反标（back-annotation），即用它和布线后的网表检查时序是否达到要求（p.150，图 6-17(a)）。

图 6-16 中器件 rslatch 的延时用 IOPATH 表示，如 `(IOPATH sb q (1.3:8.4:5.7) (4.5:7))`，三个数对应 best、typical、worst；互连延时用 INTERCONNECT 表示，如 `(INTERCONNECT d1.y c1.a (0.01:0.02:0.03))`（p.151）。延时数据也可作为约束文件使用，叫正标（forward annotation），但数据文本很大，早已被 SDC 取代（p.151-152）。在用的 SDF 版本为 2.1（1994 年 12 月）和 3.0（1995 年 5 月）（p.152）。

## 6.3 静态时序分析

STA 贯穿设计各阶段：从 RTL 综合到布局、CTS、布线和反标，直到出带（tape-out），每次都是为了检查结果是否满足约束（p.152）。器件延时由时序库提供，互连延时每阶段不同，并随 RC 负载和信号转换（slew 或 transition）更新（p.152）。各阶段目的相同，差别在准确性：综合阶段用 WLM 粗略表示互连；布局后受 I/O 和模块布图约束，比 WLM 稍准；CTS 后与时钟相关的互连参数已接近最终；布线后 RC 固定为实际值（p.152）。只有布线后的参数经延时计算才是实际结果，这时 STA 才有最大的实际应用意义（p.152）。

STA 假定设计是同步的（所有数据来自某个时钟源并送往某个时钟源），并假定所有时钟相关；根据逻辑联系，所有路径都会检查（p.152）。EDA 技术发展后还可以用多模式多端角 MMMC（multi-mode multi-corner）加快分析（p.152）。

### 6.3.1 时序约束文件

时序约束文件有多种形式，标准设计约束 SDC 较流行，它体现整个设计的时序要求，贯穿系统设计、逻辑设计和物理设计（p.152）。最新 SDC 1.4 版共有 84 条指令，与 STA 有关的大致分四类（表 6-3，p.153）：

| 类别 | 指令 |
| --- | --- |
| 设计环境约束 | set_drive、set_driving_cell、set_fanout_load、set_input_transition、set_load、set_port_fanout_number |
| 设计规则约束 | set_max_capacitance、set_max_fanout、set_max_transition |
| 时序约束 | create_clock、create_generated_clock、set_clock_latency、set_clock_transition、set_clock_uncertainty、set_disable_timing、set_input_delay、set_max_time_borrow、set_output_delay、set_propagated_clock |
| 时序特例 | set_false_path、set_max_delay、set_multicycle_path |

必须的 8 条时序约束为 create_clock、set_clock_uncertainty、set_input_delay、set_output_delay、set_load、set_driving_cell、set_operating_conditions、set_wire_load_model（p.153）。物理实施时除个别无关指令（如 set_wire_load_model）外，与逻辑综合基本一致（p.152）。

### 6.3.2 时序路径与时序分析

时序分析就是把某段路径的时序与约束要求作比较；对寄存器而言，每段待分析路径由起点和终点表示，目的是检查在时钟控制下相关数据能否被正确记录，这就是建立时间（setup）和保持时间（hold）检查（p.153）。

#### 1. 时序路径与同步

按输入（I）、输出（O）、时钟点（C）的关系，起点可为 I 或 C，终点可为 C 或 O，同步设计中有 3 大类：I2C、C2C、C2O（p.153，图 6-18）。“2”代表英文“to”，是工程简写（p.153 脚注）。三类路径分别含 input delay、时序库给出的 clk-to-Q 延时（timing arc）或 output delay；输入延迟约束与左系统的相互时间差别，输出延迟约束与右系统的差别，达不到就是系统时序违例，芯片设计中可适当修正（p.154）。

#### 2. 时序分析的建立和保持

时序库必须提供 setup 和 hold 的定义：setup 是时钟作用前沿（或后沿）到达前，同步输入 D 必须保持稳定的时间；hold 是到达后 D 必须保持稳定的时间，都是为保证数据不丢失（p.154，图 6-20）。时钟连续，为便于分析，把图 6-20 中作参考点的当前时钟叫第二个周期，这种处理叫相位移动（phase shift）（p.154-155）。寄存器带 set/reset 时，对 set 做类似 setup 的“恢复（recovery）”检查，对 reset 做类似 hold 的“清除（removal）”检查（p.155，图 6-21）；终点是存储器时，还要对地址 ADR 做“信号不变（no change）”检查，即与写能 WE 的 setup、hold 之间的要求（p.155，图 6-22）。

检查 setup 用“最差条件”时序库，违例的解决办法要么让时钟变慢（增长周期），要么缩短数据路径延迟（p.155）；图 6-23 中数据经 Q1—D2 较慢（slow logic），到达时间比 clock 要求还晚一段，这段就是 setup 违例（p.155）。检查 hold 用“最佳条件”时序库，违例的解决办法要么增长数据路径延迟，要么加快时钟到达 FF2（p.156）；图 6-24 中数据很快（fast logic），比 hold 要求还早一段，这段就是 hold 违例（p.156）。setup 怕慢、hold 怕快，方向相反，所以降频能修 setup 不能修 hold（p.155-156）。

#### 3. 时序路径类型

实际路径的起点和终点取寄存器 R 的到达点 D 和出发点 Q，再加上不含时钟的输入至输出延时，因此用 R 表示时路径分为 4 种：I2R、R2R、R2O、I2O（p.157，图 6-25）。表 6-4 的定义要求为：R2R 用时钟；I2R 用时钟和数据到达时间；R2O 用时钟和输出延迟；I2O 根据同步输入与输出的延迟分配时序要求（p.157）。图 6-26 至图 6-29 分别给出四类的 setup、hold 模型（p.157-160）。

1）R2R。setup 要求从时钟起点（C1_R1，clk_launch_edge）到终点（D2_R2）的时间小于等于同一周期时钟捕获点（C2_R2，clk_capture_edge）减去 R2_setup，组合逻辑取最坏条件 max_combo_delay（p.158）：

`clk_launch_edge + clk_to_q + max_combo_delay =< clk_capture_edge - setup_R2`（6-14a）

hold 要求从 R1 时钟端到 R2 数据端的时间大于等于前一周期的捕获沿（previous_capture_edge）加 R2_hold，组合逻辑取最佳条件 min_combo_delay（p.158）：

`clk_launch_edge + clk_to_q + min_combo_delay >= previous_capture_edge + hold_R2`（6-14b）

式（6-14a）的 clk_capture_edge 与 clk_launch_edge 已相差一个整时钟周期（捕获沿取同一周期末的沿），这个周期已含在两沿之差里，不要再额外加一个 T_period；式（6-14b）的 previous_capture_edge 则是前一周期的捕获沿（p.158）。综合阶段用理想时钟，互连延时不是实际数据，C1_R1 与 C2_R2 的实际到达延迟要等 CTS 完成后才能准确分析（p.158）。

2）I2R。只考虑与左边模块的关系，输入延时为 `input_delay = clk_to_q + combol`（p.158）。setup 从时钟发起（C_root）到 D2_R2，含左侧 clk_to_q、输出组合逻辑和本模块组合逻辑，取 max_input_delay 与 max_combo2（p.158-159）：

`clk_launch_edge + max_input_delay + max_combo2 =< clk_capture_edge - setup_R2`（6-15a）

hold 从发起到 D2_R2，取 min_input_delay 与 min_combo2（p.159）：

`clk_launch_edge + min_input_delay + min_combo2 >= previous_capture_edge + hold_R2`（6-15b）

3）R2O。只考虑与右边模块的关系，输出延时有两种（p.159）：

`ext_delay1 = external_cell + ext_net_delay + setup_R2`

`ext_delay2 = hold_R2 - min_external_cell - min_ext_net_delay`

setup 从 C_root 到输出终点，终点侧减 ext_delay1，其中三项取最坏条件（p.159）：

`clk_launch_edge + clk_to_q + max_combol =< clk_capture_edge - ext_delay1`（6-16a）

hold 从 C_root 到输出终点，终点侧加 ext_delay2，三项取最佳条件（p.160）：

`clk_launch_edge + clk_to_q + min_combol >= previous_capture_edge + ext_delay2`（6-16b）

4）I2O。setup 从时钟发起到数据输出终点，小于等于捕获沿减 out_delay，取最坏条件 max_out_delay（p.160）：

`clk_launch_edge + max_input_delay + max_combo_delay =< clk_capture_edge - max_out_delay`（6-17a）

hold 从发起到输出终点，大于等于前一捕获沿加 out_delay，取 min_out_delay（p.160）：

`clk_launch_edge + min_input_delay + min_combo_delay >= previous_capture_edge + min_out_delay`（6-17b）

#### 4. 时序分析的环境与时钟特性

与时钟相关的输入输出环境参数有 set_drive、set_driving_cell、set_load、set_fanout（p.160，图 6-30）。时钟特性参数有时钟插入延时（clock latency）、时钟不确定性（clock uncertainty，或 clock jitter）和时钟转换时间（clock transition）（p.161）。

#### 5. 锁存器的时序分析

边沿触发寄存器每周期边界传一次数据并保持状态，组合逻辑数据必须在同一周期内完成，前面 setup/hold 分析都按单周期讨论（p.161）。电平敏感锁存器随时钟高低传送信号，可在正负周期传两次数据；时钟虽只有半个周期，数据路径可通过随后的逻辑步骤补偿，这种方法称“时间借用”（time borrowing）或“周期偷用”（cycle stealing）（p.161）。高速数据通讯芯片常用锁存器，加上多时钟、多周期路径和虚假路径，使分析很复杂（p.161）。

### 6.3.3 时序分析特例

惯例上只分析单个时钟周期内的路径，实际设计中会出现“多周期路径”和“虚假路径”两个特例（p.161）。惯例检查在同一周期的起沿（launch edge）与捕沿（capture edge）之间进行；当前周期的起沿也是前一个时钟的捕沿，当前周期的捕沿也是下一个时钟的起沿（p.162，图 6-31）。

多周期路径：RAM512X16 物理尺寸大，实际延时大且不能改变（图 6-32），按单周期检查会出现 setup 违例，而实际应为 2 个周期，在约束文件中增加多周期路径定义后违例消失；若不做处理，EDA 工具会为实现惯例要求不断优化网表，无谓浪费资源（p.162）。图 6-33 的实例实际检查周期为 7，约束写法为（p.162）：

```
set_multicycle_path 7 -from {ff1} -to {ff2}
```

它要求 FSM 两个 mux 之间按 7 个周期检查，使组合逻辑延时足够大而不致违例（p.162）。

虚假路径分“功能性虚假路径”和“主观性虚假路径”。前者指路径在电路中根本不能实现，逻辑、功能上不可能到达；后者是设计者把一条很长的组合逻辑或 R2R 路径人为定义为虚假路径（p.162）。STA 会检查所有路径，因此必须先把虚假路径区别出来（p.162）。典型的功能性虚假路径是两个时钟树相互网状交叉：工具会按两条时钟树的周期做 setup/hold 计算，周期相差较大时，本属慢时钟的分权路径会对快时钟产生“虚假违例”（p.162-163）。

图 6-34 中有 4 条路径：1）A-C-C1-C2-Out；2）A-C-(Mux2/In1)-Out；3）B-B1-B2-C-C1-C2-Out；4）B-B1-B2-C-(Mux2/In1)-Out（p.163）。Sel 同时作用于两个 Mux：Sel 为 0 时路径 1 通过，Sel 为 1 时路径 4 通过，路径 2、3 永远不会用到，必须定义为虚假路径，否则工具会检查并对违例做无用优化（p.163）。虚假路径可用“from”和“to”约束单条，也可用“from”和“through”约束多条；多条路径分析复杂，应用要谨慎（p.163）。

其他特例还有“选择分析”（case analysis）、“最大延时”（max delay）和“最小延时”（min delay）。选择分析只对与时序相关的信号选择后分析，例如把 Sel 定义为可选信号（0 或 1），只跟踪路径 1 或路径 2；最大延时用于约束指定路径，可定义一段区间，图 6-35 约束“从 ffa、ffb 到 ffe”，图 6-36 约束“到 CK2 的终点”，两图标注的 Regions delay 分别为 < 15ns 与 < 8.5ns（p.163）。

### 6.3.4 统计静态时序分析

时序计算离不开 RC 参数，工艺几何参数的细微变化直接影响准确性。传统 STA 按不同工艺条件修正数据误差引起的延时，并不是最佳方案（p.163-164）。今天 CMOS 栅氧化层（SiO₂）厚度约为 14 个原子直径（硅原子直径 2.26Å），1~2 个原子的变化可达 10%~20%（p.164）。把各参数误差的统计分布用概率密度函数（PDF）描述，延时不作固定数字处理，就能克服工艺参数误差，这就是统计静态时序分析（SSTA）的基本指导方针（p.164）。

工艺误差分片间（inter-die）和片内（intra-die）：前者反映一片芯片与其他芯片间的误差，后者反映同一芯片内工艺误差引起的延时误差（p.164）。以往 9" 及更小晶圆的设计以片间误差为主，片内可忽略；当代 12" 设计中片内误差已迅速成为影响准确性的重要因素（p.164）。设计误差在 0.18μm 已不可忽视，包括信号本身的延迟、单元库线宽与间距差异、系统电压与温度；OPC、PSM 除用 RET 校正外，影响也与设计误差有关（p.164）。

SSTA 的计算过程是对大量相关随机变量的概率求解。按高斯正态分布，随机变量的 PDF 为（p.164）：

`f(x) = 1/(σ√(2π)) · e^-[(x-μ)²/(2σ²)]`（6-18）

μ 为待测值 x 的均值，σ 为标准误差（p.164）。实验用 SSTA 对某 65nm 设计布线后的 slack 计算：均值 μ = -1.240，最差剩余时间（μ-3σ）= -2.026ns；时序优化后再算，μ = 0.150，最差值仅 -0.396ns；标准差由 0.262 变为 0.182，分布更窄且右移（p.164，图 6-37）。

## 6.4 时序优化

时序分析发现设计不能满足要求，就要做时序优化去实现约束指标。引起违例的原因很多，优化方案也相应有好几种，设计者要根据实际设计分析后采取措施（p.165）。

### 6.4.1 造成时序违例的因素

逻辑综合结束时的时序分析只能证明网表在理论上成立，能否实现要经物理实施才知道，所以几乎不可能不产生违例（p.165）。成因有四种（p.165）：

1. 系统设计复杂、抽象，有些约束不合理或根本不可能实现；
2. 约束依据了不合理的 WLM，产生的网表在物理实施时无法实现；
3. 设计太大，互连线相互牵制引起违例；
4. 设计者布局不合理，物理实施后无法满足要求。

第一种要修改或修正约束文件；第二种要根据当前结果产生新 WLM，再次逻辑综合；第三种可与第二种相关，也可通过不同的布局修正解决；第四种初学者最容易遇到，有经验者同样会遇到（p.165）。

### 6.4.2 时序违例的解决方案

较小的违例用“原地优化”（IPO，in-place optimization）解决；若违例由不正确的约束引起，先修正约束再优化（p.165）。最严重的违例由物理实施复杂性引起，WLM 极不适用，这时要重新产生“专用 WLM”（CWLM，customized WLM）对门级网表重复逻辑综合，即物理综合（physical synthesis）（p.165）。

违例主要有 setup 和 hold 两种。多数情况下 setup 违例占主要成分，是 IPO 的重点；当代设计复杂性增加，hold 违例也随之增加（p.165）。IPO 早期是分别优化，即先解决 setup 违例，再处理 hold 违例，两者相互牵制，有时要重复这个过程；当今 EDA 工具可同时处理两种违例（p.165）。先 setup 后 hold 的道理是：修 setup 常靠加大驱动、缩短路径，会改变负载与线长，进而影响 hold；先把 setup 收敛，再在已定的树和布线上修 hold，改动量小（p.165-166）。

设计规则违例（DRV）也用 IPO 解决，通常包括 3 种：最大负载、最大扇出和最大转换（时间）（p.166）。书中的例子：某 50 万门设计，时钟 200MHz，0.18μm 工艺中 BUFX1 的最大负载、最大扇出和最大转换分别为 0.2pF、16 个门和 2ns；时序检查发现违例就用 IPO 优化（p.166）。与设计规则相似的问题还有超长互连，可用插入“重复器件”（repeater）解决，一般在布局后首先处理（p.166）。

### 6.4.3 原地优化

IPO 事实上就是时序优化，可以应用多次，例如时钟树综合前、后各一次，布线前、后各一次；前 3 次可在早期解决问题，只有布线后第 4 次 IPO 且满足约束文件才是最终期望的结果（p.166）。常见方法有（p.166）：

1. 挑选并替换驱动能力不同的逻辑单元（re-sizing），最简单、最重要（图 6-38）。书中算例：总负载 0.7（d = 0.2，e = 0.2，f = 0.3），按单元库资源选用 C 单元，负载 0.7 时总延时 0.026，替换 A 单元的 0.035（p.166）。
2. “克隆”（cloning）法，复制一个逻辑单元去分担负载（图 6-39）。
3. 添加“缓冲器”（buffering），或用缓冲器替代两个反相器（图 6-40）。

IPO 只对当前网表做逻辑优化，不做逻辑重组（logic structuring），所以后期做逻辑等效检查（LEC）很简单；逻辑重组还包括“变换”、重新设计扇入扇出、“分组”法和交换输入连接（swap commutative pins），更深入的方案见第 10 章（p.166）。个别违例也可用“工程更改计划”（ECO，engineering change order）实现，它是 IPO 的互补方案，更重要的用途是修正逻辑问题（p.167）。

## 6.5 总结

版图参数提取用于仿真和时序分析。STA 随布线完成而进行：先提取布线后的寄生参数并用 SPF 记录，再做延时计算得到 SDF（p.167）。按约束文件和多种 PTV（最佳、典型、最差）条件，分析不同路径类型（R2R、I2R、R2O、I2O）和时钟定义，检查 setup、hold 及其他约束是否满足；纳米设计中还要考虑电源（第 7 章）与噪声、信号完整性（第 8 章）的影响（p.167）。

时序分析还涉及多周期路径、虚假路径以及最大、最小路径等特例。违例的解决办法首先选 IPO，然后才是逻辑再综合；纳米工艺的新课题包括 OCV 与 CPPR 的分析方案和与可制造性相关的 SSTA（p.167）。工程中 RC 提取和 STA 也可在布局后、CTS 后进行（p.167）。
