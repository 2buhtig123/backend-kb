## 10.1 时序验证

芯片物理设计完成后，流片（tape out）前的最终检查工作与签发核实（sign-off）包括时序验证、物理验证和逻辑功能验证三大任务（p.220）。时序验证采用时序分析等方法验证设计是否满足时序收敛，这些检验工作包括反向标定（back-annotation）、时序与功耗的检验、时序与信号完整性的检验，以及当代低功耗纳米先进设计中的多模式多端角 MMMC（multi-mode multi-corner）检验（p.220）。

### 10.1.1 反标注

RTL 编码并仿真验证后，由综合工具产生门级网表。检查门级网表时序更准确的方法可用 PLE（物理布图参数，用来取代传统 WLM 或综合时产生的延时预估 SDF 文件）；布局布线后的动态仿真验证由最终布线后产生的 SDF 完成。这种用 SDF 做动态仿真验证的方法称为反向标定（back-annotation）。用最终布线后的真实 RC 信息反标到仿真中，是确认芯片在实际工作条件下时序行为的重要手段（p.220）。

为获得准确仿真结果，需提供以下影响时序的参数：驱动能力、互连线参数、总负载、环境因素即工艺温度电压 PTV 条件（p.220）。关于通过提取互连线参数 RC 产生 SPF 文件、再计算产生 SDF 文件的方法与过程，见第 6 章 6.1 节和 6.2 节。第 2 章讨论的 liberty 时序库有三种 PTV 条件：最慢 slow/worst、典型 typical/normal、最快 fast/best，而典型仿真器只能在一种 PTV 下进行单次仿真。因此需要分别用最慢的 SDF 对最快的时钟信号做 setup 检查，再用最快的 SDF 对最慢的时钟信号做 hold 检查（p.220-221）。

逻辑综合用时序库做时序分析时，最普遍应用为最佳、典型、最差三种时序库；每种库根据相应 PTV 或工作条件建立，其标定数据称为“工艺角”（process corner）。物理实施布线后，由不同工艺角导出“RC 工艺角”；多种“工艺角”与布线后的“RC 工艺角”合称“多端角”（p.220-221）。

### 10.1.2 时序分析与功耗分析

电源网络设计和功耗分析是两项紧密关联的工作。工程应用中，前者在做电源预算规划时为芯片供电提供可靠保障，后者在做功耗分析时对其规划方案的最终结果进行检查并分析（p.221）。

在做时序分析时，功耗分析结果须符合电源预算，且不能对时序产生违例。第 7 章已分别讨论了静态功耗、动态功耗和电压降的基本理论与方法；若布局布线方案多次改动，最终签核时必须再次检查电源网络、电压降与功耗结果（p.221）。

MSMV、PSO、DVFS 等低功耗技术的应用使功耗分析工作量与复杂度增加；芯片温度效应也会影响功耗泄漏、信号完整性与时序，需要由热力学引擎做“温度意识（temperature-aware）”分析。引用电源网络分析结果做时序分析时须特别关注这些因素（p.221）。随着 SSTA 发展，电压和温度波动引起的统计误差计算分析也将成为重要任务（p.221）。

### 10.1.3 时序分析与信号完整性

深亚微米早期 SI 分析独立完成；后来经验表明应将其与时序分析一起进行。第 8 章分析了串扰与电压降的关系和串扰引起延迟的问题，串扰预防主要在布线阶段实现（p.221）。

在低功耗设计中，MSMV、MTCMOS 与电平转换单元（level shifter）的使用给 SI 分析带来新的复杂性：不同电压与阈值条件下进行噪声分析，需要调用不同的晶体管级仿真模型来计算信号串扰，并进一步分析对时序的作用（p.221-222）。在 65nm 及以下设计中，若仅用最坏时序条件做 SI 分析会带来过于悲观的结果，因此常结合 SI 和电压降数据对关键路径进行仿真分析，以过滤悲观误差、提高准确性和可靠性（p.222）。最终 sign-off 时，应根据功耗分析和电压降分析的合格结果，再结合信号完整性做最终 MMMC 时序分析（p.222）。

### 10.1.4 用 MMMC 做时序验证

65nm 以下设计中，MMMC 逐渐成为时序验证的基本要求。MMMC 关键是建立或提供多模式多端角数据并合理组合。主要模式为标准时序约束模式，其他还有扫描模式、BIST、DVFS 等；多端角包括半导体器件条件（不同 PTV 时序库）与 RC 条件（提取与 derating）（p.222）。

图 10-1 显示：视图由“单个延时端角 + 单个约束模式”组成；延时端角包含单个 RC 端角、单组库、PTV 参数、Derating、工作条件；RC 端角包含 RC 控制值、电容值表、电容参数；库数据组包含时序库、噪声库；模式包含时序约束、常数、特例（p.222-223）。MMMC 分析时，设计网表、约束文件、物理库、时序库等一起输入；时钟树综合后即可分模式分端角做时序分析（p.223）。

1. 单模式单端角 SMSC（single-mode single-corner）是 MMMC 分析的前提和基础。除 setup/hold 外，时序分析还包括时序特例、false path、multicycle、time borrowing、时钟门控信号选择等。早期原型设计（如逻辑综合）常用典型时序库（p.223）。TDD 初期只能单次读入一种约束与一种库；中期可同时读入一种约束与两种库做 setup/hold；MMMC 则可同时读入多模式、多约束、多库、多 RC 文件（p.223）。

例 10-1：

```tcl
create_analysis_view -name view1 -delay_corner dc_wc -constraint_mode func_mode
create_analysis_view -name view2 -delay_corner dc_tc -constraint_mode func_mode
create_analysis_view -name view3 -delay_corner dc_bc -constraint_mode func_mode
```

（p.223）。

2. 两个时序库或两个端角。常用最佳/最差时序库 BC/WC 做静态时序分析，多见于 130nm 以上、不强调低功耗的消费类产品（p.223）。

3. 最佳和最差时序库与时序“降额”。选用 BC/WC 库时要考虑转换时间范围，不一致时需做 time derating。例 10-2：对 BC/WC 库做 10%～20% 校正，BC 为 early ×1.0、late ×1.1；WC 为 late ×1.0、early ×0.8（p.223-224）。

4. 片上误差 OCV 与共同路径悲观消除 CPPR。12" 裸片需考虑 OCV；为克服 CPPR 影响可对 OCV 做调节。例 10-3：setup 用最大时序库“max delay + late path”、最小时序库“early clock”；hold 用最小时序库“min delay + early path”、最大时序库“late clock”。OCV 模式下有时还要对 CPPR 特例计算（p.224）。

5. RC 端角定义。RC 提取根据代工厂提供的多种 PTV 与工艺条件产生电容表（cap table）文件；布线后还可用电阻电容标定因子标定。每个电容表格文件即一个 RC 端角。例 10-4：cbest 最佳电容、cworst 最差电容、rcbest 最差 RC、rcworst 最佳 RC、typical 典型 RC（p.224）。

6. 模式与端角选择。组合数可能很大，例如 3 种模式、3 种时序库端角、4 种 RC 端角共 36 种组合。图 10-3 用视图方法保留对时序影响大的视图、裁剪影响小的视图，以加快收敛（p.224-225）。

例 10-5：

```tcl
####### Create Views #######
create_analysis_view -name f1-typ-rcworst -constraint_mode f1 -delay_corner dc-typ-rcworst
create_analysis_view -name f1-worst-rctyp -constraint_mode f1 -delay_corner dc-typ-rctyp
create_analysis_view -name f2-typ-rcworst -constraint_mode f2 -delay_corner dc-typ-rcworst
create_analysis_view -name f2-worst-rctyp -constraint_mode f2 -delay_corner dc-typ-rctyp

####### Select active views for Setup and Hold #######
set_analysis_view -setup [list f1-typ-rcworst f1-worst-rctyp f2-typ-rcworst f2-worst-rctyp] \
  -hold [list f1-worst-cworst f1-best-cworst f1-best-cbest f2-worst-worst \
         f2-best-cworst f2-best-cbest test-worst-cworst test-best-cworst test-best-cbest]
```

（p.225）。

### 10.1.5 MMMC 实例

用 MMMC 做时序验证主要在时钟树综合阶段进行约束并分析，包括环境建立、CTS 前后时序优化、SI 收敛等（p.225）。

1. 建立环境。例 10-6 用 Tcl 脚本定义三种模式 f1/f2/test、三种时序库 worst/typical/best、四种 RC 端角 cbest/cworst/rcworst/typical（p.225-226）：

```tcl
####### create the Constraint Modes #######
create_constraint_mode -name f1 [list $data/constrs/func1.sdc]
create_constraint_mode -name f2 [list $data/constrs/func2.sdc]
create_constraint_mode -name test [list $data/constrs/test.sdc]

####### create the Library sets #######
create_library_set -name libs-worst -timing [list $libs/t90wc.lib]
create_library_set -name libs-typical -timing [list $libs/t90tc.lib]
create_library_set -name libs-best -timing [list $libs/t90bc.lib]

####### create the RC corners #######
create_rc_corner -name rc-cbest -cap_table $data/rc/c90bc.txt
create_rc_corner -name rc-cworst -cap_table $data/rc/c90wc.txt
create_rc_corner -name rc-rcworst -cap_table $data/rc/c90wrc.txt
create_rc_corner -name rc-typical -cap_table $data/rc/c90typ.txt
```

例 10-7 定义延时端角（p.226）：

```tcl
create_delay_corner -name dc-typ-rcworst \
  -library_set libs-typical \
  -rc_corner rc_rcworst \
  -opcond_library tcbn90lphptc \
  -opcond NCCOM
create_delay_corner -name dc-worst-rctyp ... # dc 最差、RC 典型
create_delay_corner -name dc-worst-cworst ... # dc 最差、RC c 最差
create_delay_corner -name dc-best-cbest ...   # dc 最佳、RC c 最佳
```

定义好约束模式、时序库端角和 RC 端角后，计算与结果分析依赖 EDA 工具，必要时对时序库做 derating（p.226）。

2. CTS 与时序收敛。MMMC 从时钟树综合阶段开始，目标是各模式/端角组合下时钟到达叶单元的偏差最小（p.226-227）。例 10-8（p.227）：

```tcl
create_analysis_view -name view1 -delay_corner dc_wc -constraint_mode func_mode
create_analysis_view -name view2 -delay_corner dc_tc -constraint_mode func_mode
create_analysis_view -name view3 -delay_corner dc_bc -constraint_mode func_mode
set_analysis_view -setup {view1 view2} -hold {view3}
```

3. SI 与时序收敛。图 10-4：先定义多个 MMMC 视图并分别做 RC 提取、STA、SI 分析，对关键路径标识；将各视图噪声违例网络取并集，经 SI IPO MMMC aware 优化后调用布线工具做 ECO 布线收敛（p.227）。

4. SPEF 与 SDF 方法。例 10-9：SPEF 方式用 max1.spef、max2.spef、min1.spef、min2.spef；SDF 方式用 max1.sdf、max2.sdf、min1.sdf、min2.sdf；RC 端角文件必须完整（p.227）。例 10-10：

```tcl
set_analysis_view -setup {view1 view2 view3} -hold {view1}
```

（p.228）。

5. 低功耗 CPF 方法。MSMV 中的电平转换单元、隔离单元、电源开关、SRPG 等特殊单元使 MMMC 更复杂。图 10-5 显示 CPF 可定义时序库集合、工作端角、电源域、功耗模式、标称条件，进而生成分析视图，无需修改设计其他部分（p.228）。

## 10.2 物理验证与芯片组装

90nm 以下设计除传统 DRC、电路检查外，还需光刻检查与可制造性检查，最后完成芯片集成或组装（p.228）。

### 10.2.1 设计规则检查

DRC 最基本目标是与几何尺寸相关的检查（见第 2 章 2.2 节）。通常先对芯片布线后顶层做基本检查，再将底层标准单元 GDSII 合并检查（p.228）。由于现代硅片打磨采用 CMP 工艺，为保持每层材料均匀性需金属填充（metal fill）以满足金属密度，因此 DRC 也包括对完成布线后每一层金属密度的检查（p.228-229）。深亚微米设计还需根据“最小面积规则”MAR 对浮动金属面积进行检查；在纳米以下设计中，最小面积规则检查是必须的，MAR 也被称为最大悬浮面积 MFA（p.229）。此外，DRC 还需检查工艺天线效应 PAE，它是在布线阶段完成、做 DRC 时不可忽视的任务（p.229）。

### 10.2.2 光刻检查与可制造性

从方法上看，光刻检查是 DRC 的特例，也可以说是 DRC 的扩展（p.229）。新一代布线工具结合后期版图检查，已具有光刻驱动（litho-driven）、光刻预防（litho prevention）、光刻补救（litho repair）和光刻修正或固定（litho fix）功能。在半导体工艺中，波长 193nm 浸没式光刻技术（immersion lithography）可延伸用于 45nm 节点设计；由于 OPC 与 PSM 规则要求，DRC 还需对布线最大宽度、布线伸出（wire extension）长度、布线脚边（wire corner）等进行校正和检查（p.229）。

DFM 近年来得到大量讨论，由于被广泛引用，其意义已变得模糊：有人认为 DFM 就是 OPC，有人认为 DFM 是光刻工艺中的分辨率增强技术 RET，有人认为 DFM 改成可量产性设计 DFY 更合适，甚至有人认为 DFM 可包括 SSTA、OCV、功耗管理和低功耗分析等（p.229）。

### 10.2.3 电路检查

电路检查主要任务是 LVS（见第 2 章 2.3 节）。芯片设计最终验证阶段通常先对芯片顶层布线做基本检查，包括是否有短路、开路等，再将底层标准单元 GDSII 合并做 LVS（p.229）。电路检查包括电源与接地和信号线连接两大部分，并对布线后的电路特征进行检查。它包括与功耗相关的直流限度 DC limit 和交流限度 AC limit：DC limit 检查电压降和满足功耗要求中不出现“线自热”而导致连线失效；AC limit 检查信号线在不同时钟频率条件下的交流特性，是功耗分析的一部分（见第 7 章 7.3.4 节）（p.229）。

### 10.2.4 芯片集成

芯片集成是物理设计最后一道工序。层次化设计需先完成各大模块时序与物理验证，产生布图规划、电源规划、最终门级网表、SDC、LEF、DEF、SPEF、SDF、GDSII、时钟树报告、时序报告等；顶层可打平后做同样验证（p.229-230）。之后还需逻辑等效验证（见 10.3 节）。流片前还需添加公司 logo、密封线（图 10-6），并制作芯片单元与封装管脚之间的 bonding 图（图 10-7）（p.230）。

## 10.3 逻辑等效验证与 ECO

据统计，一半以上芯片设计因验证问题需修改，其中约 3/4 为功能问题（p.230）。设计早期可修改 RTL；临近最终签核则用工程改变命令 ECO（engineering change order）实现（p.230）。

### 10.3.1 形式验证

最终签核前必须再次验证。验证包括功能验证与形式验证（conformal verification），后者亦称逻辑等效验证或逻辑等效检查（logic equivalency check）。本章仅讨论逻辑等效验证在最终签核中的作用（图 10-8）（p.231）。

### 10.3.2 逻辑等效验证

从 RTL 到门级网表，综合与物理优化均会更新网表，因此逻辑等效检查十分重要（p.231）。形式验证可用于 ASIC、COT、SoC 的打平式或层次式设计；最简单应用是比较两个网表，如 CTS 前后网表。随着 EDA 发展，逻辑等效验证进一步扩展为 RTL 与版图的晶体管级验证 LVR（layout versus RTL）（p.231）。

### 10.3.3 验证与 ECO

从 RTL 综合产生门级网表开始，功能验证持续进行，RTL 与门级网表不断更新直至 RTL“冻结”（frozen）。若改动较小（如小于 3%），可通过 ECO 对布局布线做局部更新（p.231-232）。

布局或布线阶段可用递增式 ECO 修正物理设计。按发现问题时期，ECO 分为 tape-out 前与 tape-out 后。tape-out 前灵活性大：可用递增式布局/布线添加或删除逻辑门、buffer、手动改线（p.232）。tape-out 后限制大：只能对上层金属做有限修改，不能新增逻辑门，但可利用预先布放的备用逻辑门（spare gate），按需连接 buffer、inverter、与/或/与非/或非门等；spare gate 在门级网表阶段读入并随机布放（p.232）。测试阶段发现问题仍可用 FIB（focused ion beam）对硅片截面做微型手术实现 ECO（p.232）。

## 10.4 数据交换及检查

### 10.4.1 数据交换

数据交换是为保证芯片成功流片，设计方与制造商之间需交换的数据（p.232）。设计方需提供：GDSII 版图文件、DRC/LVS 规则文件、DRC/LVS 结果文件（p.232）。IP 合并时制造厂会合并版图并做 DRC/LVS，此时设计方还需提供 SPICE 网表。给封装厂的封装导线表包括：裸片管脚坐标、裸片与封装管脚对应关系、封装管脚名称（p.232）。

晶圆厂通常向设计方提供工艺包（含工艺规则与检查规则文件），有的还提供远程登录终端，光照前可检查光刻胶片图，重点确认 IP 合并部分连接完好（p.233）。

### 10.4.2 检查内容及方法

严格意义上所有数字集成电路都应完成时序、物理、逻辑三种验证。部分设计者会简化：0.13μm 及以上可不做 MMMC；0.18μm 及以上噪声不明显且主频不高时可不做 SI；不关心功耗且对电源网格有信心时可不做功耗分析；也有不做形式验证的情况（p.233）。

## 10.5 总结

最终检查与 sign-off 是流片前最后一道关隘。虽然静态时序分析等早期已初步完成，最终签核仍需逐项检查；越早发现问题，ECO 成本越低（图 10-10）（p.233）。时序、物理、逻辑三类验证相互依赖；只有完成 RTL 到 GDSII 并 sign-off、晶圆厂流片测试通过，芯片设计才算真正完成（p.233-234）。
