数字集成电路从 RTL 到 GDSII 的全流程中，不同 EDA 工具之间需要大量中间文件来传递网表、约束、版图、寄生参数、时序与功耗信息。原书附录 1 以总表形式列出了这些常用库文件与文档及其在流程中的作用，附录 2-14 对其中 13 种主要文件格式逐一举例说明，附录 15、16 则给出国际单位制及 SI 前缀。本文将上述附录内容压缩成一份后端工程师速查手册，所有字段与语法片段均严格来自原书，不补充书中未出现的格式细节。

若按数据性质归类，这些文件大致可分为五类：硬件描述语言（VHDL、Verilog HDL）、设计约束（SDC、CPF）、版图与物理库（GDSII、LEF、DEF）、时序/功耗库（Liberty、SDF、TCF）、寄生参数与信号完整性（VCD、DSPF、RSPF、SPEF、TWF）。阅读时可先查总表定位用途，再对照各节关键字段。

## VHDL / Verilog HDL（附录 2、3）

VHDL 与 Verilog HDL 均为数字系统的硬件描述语言。VHDL 由美国国防部于 1981 年开发，1987 年成为 IEEE Std-1076 标准，1993、2000、2002 年继续修订；语言描述由实体说明（entity declaration）与构造体（architecture body）两部分组成，实体说明定义模块外部端口与连接关系，构造体说明内部具体构造。Verilog HDL 由 Gateway Design Automation 公司 1984 年开发，1995 年成为 IEEE Std1364-1995 标准，2001 年发布 Std1364-2001 标准；其描述可分为行为级与结构级，硬件描述多采用自顶向下的层次化设计方法。

关键语法片段（原书示例）：

```vhdl
-- VHDL
library IEEE; use IEEE.STD_LOGIC_1164.ALL;
entity DFF is
  Port(d, clk, reset : in  STD_LOGIC;
       q:             out STD_LOGIC);
end;
architecture flip_flop of DFF is
begin
  Process(clk) begin
    if RISING_EDGE(clk) then
      if reset = '1' then q <= '0';
      else q <= d;
      end if;
    end if;
  end process;
end;
```

```verilog
// Verilog HDL
module DFF(q, d, clk, set, reset);
  input d, clk, set, reset;
  output q;
  reg q;
  always @(posedge clk)
    if(set)        q <= 1'b1;
    else if(reset) q <= 1'b0;
    else           q <= d;
endmodule
```

两者并非后端专用文件，但所有后续物理设计信息均来自 RTL 描述，因此附录 1 将其列在最前，本笔记亦合并简述。

## VCD（附录 4，p.238）

**用途**：VCD（Value Change Dump）文件记录电路中部分选定变量在仿真时间轴上的跳变信息，通常由 Verilog 仿真器产生，用于芯片动态功耗计算。

**文件基本结构**：VCD 采用 ASCII 格式，语法简单，共 12 条命令，可概括为文件头、变量声明、数值转存三大部分。文件头部分给出产生日期、工具版本与仿真时间单位；变量声明部分用变量标识码与作用域把 Verilog 中需要记录变化值的变量重新命名；数值转存部分按仿真时间递增记录各变量值，并可通过 `$dumpoff` / `$dumpon` 控制记录启停。

**关键字段或语法片段**：

- `$comment`：注释。
- `$date`：文件生成日期。
- `$enddefinitions`：声明部分结束。
- `$scope` / `$upscope`：定义变量所属层次，可为 module、task、function、begin 或 fork。
- `$timescale`：仿真时间单位。
- `$var`：变量标识码声明，格式如 `$var trireg 1 *@ net1 $end`。
- `$version`：仿真工具版本。
- `$dumpvars`：记录变量初始值。
- `$dumpall`：记录当前时刻所有变量值。
- `$dumpoff` / `$dumpon`：暂停/恢复记录。

书中示例片段：

```text
$date Oct 10, 2000 09:24:35 $end
$version VERILOG-SIMULATOR 1.0a $end
$timescale 10ns $end
$scope module top $end
  $scope module m1 $end
  $var trireg 1 *@ net1 $end
  $var trireg 1 *# net2 $end
  $var trireg 1 *$ net3 $end
  $upscope $end
$enddefinitions $end
$comment This is a single-line comment $end
#500  $dumpvars x*@  x*#  x*$  bx(k  bx{2  $end
#520  1*$ 
#535  $dumpall 0*@ 1*# 0*$ bz(k b111000101z01x {2 $end
#1000 $dumpoff x*@ x*# x*$ bx(k bx{2 $end
#2000 $dumpon  z*@ 1*# 0*$ b0(k bx{2 $end
```

书中指出，`$dumpvars` 指定了所有要记录的变量和变量的初始值；`$dumpall` 记录当前时刻所有变量的值；`$dumpoff` 表示停止记录所有变量的值；`$dumpon` 表示恢复记录所有变量的值。示例中 `*@`、`*#`、`*$` 等奇怪符号即为 `$var` 命令定义的变量标识码。

## SDC（附录 5，p.239）

**用途**：SDC（Synopsys Design Constraints）基于 TCL 格式，由 Synopsys 开发，后由 Cadence 移植用于时序控制的布局布线设计。SDC 1.7 版于 2007 年 3 月发布，用于对电路的时序、功耗、面积等进行约束，使芯片满足设计规范。

**文件基本结构**：SDC 文件包含版本、基本单位、设计约束与注释四大部分，其中设计约束是主要内容，版本、基本单位与注释三部分不是必须出现。基本单位由 `set_units` 指定电阻、电容、电压、电流、功耗、时间等单位；注释以 `#` 开头。SDC 1.7 中与设计约束相关的命令共 46 条，分为 9 类：工作环境、线负载模型、系统接口、时序约束、时序特例、设计规则约束、面积约束、功耗约束、逻辑赋值。

**关键字段或语法片段**：

- `set_sdc_version`：指明 SDC 版本。
- `set_units`：设置电阻、电容、电压、电流、功耗、时间等基本单位。
- `set_operating_conditions`：设置最快与最慢工作条件对应的库文件与工作环境。
- 线负载模型：`set_wire_load_mode`、`set_wire_load_model`、`set_wire_load_min_block_size`、`set_wire_load_selection_group`。
- 系统接口：`set_drive`、`set_driving_cell`、`set_input_transition`、`set_load`、`set_fanout_load`、`set_port_fanout_number`。
- 时序约束：`create_clock`、`set_clock_groups`、`set_clock_uncertainty`、`set_clock_latency`、`set_clock_transition`、`set_input_delay`、`set_output_delay`、`set_propagated_clock`、`set_max_time_borrow`。
- 时序特例：`set_false_path`、`set_multicycle_path`、`set_max_delay`、`set_min_delay`。
- 设计规则约束：`set_max_capacitance`、`set_min_capacitance`、`set_max_fanout`、`set_max_transition`。
- 面积约束：`set_max_area`。
- 功耗约束：`set_max_dynamic_power`、`set_max_leakage_power`。
- 逻辑赋值：`set_case_analysis`、`set_logic_dc`、`set_logic_one`、`set_logic_zero`。

## GDSII（附录 6，p.241）

**用途**：GDSII 是业界标准版图数据格式，由 Calma 公司开发，最早用于版图工具 Edge。它采用二进制格式描述版图几何图形、拓扑关系、结构层次等所有版图信息，特点是文件数据量小、不可直接阅读。GDSII 不仅用于电路设计者与代工厂之间交换信息，也可用于寄生参数提取、功耗分析与电压降分析。

**文件基本结构**：GDSII 文件可看作由若干基本单位顺序组成，每个基本单位以 `total record length` 开头，到下一条 `total record length` 之前为一个完整记录。每个基本单位包含记录类型（record type）、数据类型（data type）与数据（data）三部分：记录类型占一个字节，表示记录内容；数据类型占一个字节，指明数据表示方法；数据部分的字节数由总长度减去记录类型与数据类型所占字节得到。不同记录类型标号从 00 到 69，共 70 种情况。

**关键字段或语法片段**：

- `total record length`：本记录所占字节数，占一个字（word）。
- `record type`：记录内容类型，例如十六进制 `0002` 表示 GDSII 版本号，`0102` 表示文件最后一次修改和访问时间，`0206` 表示 GDSII 文件名。
- `data type`：数据编码方式，书中列出 7 种：
  - 0：无数据；
  - 1：位阵列；
  - 2：两字节符号整数；
  - 3：四字节符号整数；
  - 4：四字节实数（已不再使用）；
  - 5：八字节实数；
  - 6：ASCII 字符串。

以两字节符号整数为例，最高位为符号位，“0”代表正，“1”代表负，其余 15 位表示数值；四字节符号整数与之类似，只是位数扩展到 32 位；四字节实数和八字节实数由符号、指数、尾数三部分组成，但四字节实数现已不再使用。

书中示例说明：

```text
0006 0002 0258 001C 0102 0058 0009 0003 0000 ...
```

其中 `0006` 表示本基本单位 6 字节，`0002` 表示记录内容为版本号，数据类型 `02` 为两字节符号整数，`0258` 即版本号 600（十进制）。`001C` 表示下一记录 28 字节，`0102` 表示最后一次修改时间，数据类型 `02`，后续为日期时间数据。

## LEF（附录 7，p.243）

**用途**：LEF（Library Exchange Format）是自动布局布线所必需的库文件，最早由 Cadence 公司开发。随着工艺尺寸缩小、物理效应增多，LEF 不断更新：5.4 版增加 CLEARANCEMEASURE、USEMINSPACING、MANUFACTURINGGRID；5.5 版增加 MAXVIASTACK、layer implant；5.6 版增加对 45 度布线的支持。

**文件基本结构**：LEF 文件分为 **Technology LEF** 与 **Cell LEF** 两大部分：Technology LEF 描述工艺信息、设计规则与通孔信息；Cell LEF 描述单元库中各单元的属性与几何形状。

**关键字段或语法片段**：

- `UNITS`：数据库单位与国际标准单位的换算，目前支持 100、200、1000、2000 四种转换因子。示例：
  ```text
  UNITS
    DATABASE MICRONS 2000 ;
  END UNITS
  ```
- `LAYER`：工艺层定义，包含 `TYPE`、`WIDTH`、`SPACING`、`SPACING ... RANGE ... USELENGTHTHRESHOLD`、`PITCH`、`DIRECTION`、`RESISTANCE RPERSQ`、`CAPACITANCE CPERSQDIST`、`EDGECAPACITANCE`、`ANTENNACUMAREARATIO` 等。
- `VIA` / `VIARULE`：通孔定义。完整通孔由两个互连层和一个 cut 层组成；`VIARULE` 用于定义通孔阵列，`ENCLOSURE` 定义 cut 层距金属边界的距离；`TOPOFSTACKONLY` 限制只能在通孔堆叠时使用。
- `SPACING`：同网名间距规则，如 `SAMENET metal1 metal1 0.23 ;`，`STACK` 允许跨金属层堆叠 cut。
- `SITE`：最小布局单位，如：
  ```text
  SITE tsm12site
    SYMMETRY y ;
    CLASS core ;
    SIZE 0.460 BY 3.690 ;
  END tsm12site
  ```
- `MACRO`：单元定义，每个 `MACRO` 代表一个单元。包含 `CLASS`、`FOREIGN`、`ORIGIN`、`SIZE`、`SYMMETRY`、`SITE`、若干 `PIN` 以及 `OBS`。
- `PIN`：单元端口定义，包含 `DIRECTION`、`USE`、`SHAPE`、`PORT`、`LAYER`、`RECT`。
- `OBS`：单元不可布线区域。

书中 METAL1 层与 INVX20 单元示例片段：

```text
LAYER METAL1
  TYPE ROUTING ;
  WIDTH 0.160 ;
  SPACING 0.180 ;
  SPACING 0.18 LENGTHTHRESHOLD 1.0 ;
  SPACING 0.22 RANGE 0.3 10.0 USELENGTHTHRESHOLD ;
  SPACING 0.60 RANGE 10.05 100000.0 ;
  PITCH 0.410 ;
  DIRECTION HORIZONTAL ;
  RESISTANCE RPERSQ      8.3000e-02 ;
  CAPACITANCE CPERSQDIST 1.8831e-04 ;
  EDGECAPACITANCE        9.7858e-05 ;
  ANTENNACUMAREARATIO    500 ;
END METAL1

MACRO INVX20
  CLASS CORE ;
  FOREIGN INVX20 0.000 0.000 ;
  ORIGIN 0.000 0.000 ;
  SIZE 5.980 BY 3.690 ;
  SYMMETRY x y ;
  SITE tsm12site ;
  PIN Y
    DIRECTION OUTPUT ;
    PORT
      LAYER METAL1 ;
      RECT 4.715 0.680 4.975 2.980 ;
      RECT 4.490 0.870 4.715 2.775 ;
    END
  END Y
  PIN VSS
    DIRECTION INOUT ;
    USE ground ;
    SHAPE ABUTMENT ;
    ...
  END VSS
  PIN VDD
    DIRECTION INOUT ;
    USE power ;
    SHAPE ABUTMENT ;
    ...
  END VDD
  OBS
    LAYER METAL1 ;
    RECT 0.820 1.030 1.040 1.250 ;
    ...
  END
END INVX20
```

## Liberty（附录 8，p.248）

**用途**：Liberty（以 `.lib` 结尾）由 Synopsys 开发，用于描述物理单元的时序和功耗信息。为保证精度，延时多采用非线性查表（look-up table）或分段线性方法；功耗与延时通常作为输入信号转换时间与输出负载的函数。

**文件基本结构**：Liberty 库文件大致分为两部分：单元库基本属性与每个单元的具体信息。库头部分定义库名、版本、日期、PTV、电压/电流/电容/时间单位、信号阈值百分比、查表模板等；单元部分给出 `cell`、`pin`、`timing`、`power` 等数据。查表模板 `lu_table_template` 是 Liberty 文件的最大特色，通过 `variable_1`、`variable_2`、`index_1`、`index_2` 定义索引，`values` 给出对应值。

**关键字段或语法片段**：

- `library(...)`：库名称与整体属性。
- `delay_model : table_lookup ;`：延时模型为查表。
- `date`、`comment`、`revision`：日期、注释、版本。
- `time_unit`、`voltage_unit`、`current_unit`：基本单位。
- `input_threshold_pct_fall / rise`、`output_threshold_pct_fall / rise`、`slew_lower_threshold_pct_fall / rise`、`slew_upper_threshold_pct_fall / rise`：阈值百分比。
- `nom_process`、`nom_temperature`、`nom_voltage`、`operating_conditions`：工艺/温度/电压及互连线模型。
- `lu_table_template(...)`：查表模板，用 `variable_1`、`variable_2`、`index_1`、`index_2` 定义索引。
- `cell(...)`：单元定义。
- `area`、`cell_footprint`、`cell_leakage_power`：面积、可交换 footprint、泄漏功耗。
- `pin(...)`：端口定义，含 `capacitance`、`direction`、`function`。
- `internal_power()` / `leakage_power()`：功耗信息，含 `related_pin`、`when`、`fall_power`、`rise_power`。
- `timing()`：时序信息，含 `related_pin`、`timing_sense`、`timing_type`、`cell_fall`、`cell_rise`、`fall_transition`、`rise_transition`。
- `ff(...)` / `clocked_on` / `next_state`：触发器功能定义。
- `fall_constraint` / `rise_constraint`：建立/保持时间查表。

书中查表模板示例：

```text
lu_table_template(delay_template_2x2){
  variable_1 : total_output_net_capacitance;
  variable_2 : input_net_transition;
  index_1("1000.0, 1001.0");
  index_2("1000.0, 1001.0");
}
rise_transition(delay_template_2x2){
  index_1("0.01, 0.4532");
  index_2("0.01, 1.2");
  values("0.131455, 0.131036",
         "4.19211, 4.13413");
}
```

其中 `variable_1` 代表输出端连线负载电容，`variable_2` 代表输入信号斜率；当输出端负载为 0.01、输入斜率为 0.01 时，输出上升时间为 0.131455；负载 0.4532、斜率 1.2 时，上升时间为 4.13413。

## DEF（附录 9，p.255）

**用途**：DEF（Design Exchange Format）由 Cadence 开发，用于描述电路物理设计信息，既包含电路连接关系，也包含布局布线后单元与互连线的具体物理信息。原书指出，有了 LEF 与 DEF 文件即可完整地了解一个设计。

**文件基本结构**：完整 DEF 语法见原书表 A-13，包含头语句与若干 section。实际文件中并非所有语句都会出现，不同阶段使用的 DEF 内容不同。`statement` 表示该语法不包含嵌套定义，`section` 表示可包含其他嵌套定义。LEF 与 DEF 相分离的方式虽然增加了工具间交互的繁琐性，但提高了设计的保密程度。

**关键字段或语法片段**：

- `VERSION`、`DIVIDERCHAR`、`BUSBITCHARS`：版本与分隔符。
- `DESIGN ...` / `END DESIGN`：设计名，所有描述位于其间。
- `UNITS`：单位换算。
- `DIEAREA`：芯片面积，如 `DIEAREA (0 0)(100 100)`。
- `ROW`：行定义，如 `ROW row_1 siteA 1000 1000 N DO 100 BY 1 ;`。
- `TRACKS`：布线轨道，如 `TRACKS Y 540 DO 4192 STEP 540 LAYER METAL1 ;`。
- `GCELLGRID` / `VIAS` / `STYLES`：网格、通孔与线型。
- `COMPONENTS`：单元实例及放置信息。
- `PINS` / `PINPROPERTIES`：I/O 端口及端口属性。
- `NETS` / `SPECIALNETS`：互连线网表。
- `BLOCKAGES`、`SLOTS`、`FILLS`、`REGIONS`、`GROUPS`、`SCANCHAINS` 等。

书中示例：

```text
DESIGN Demo_chip
...
DIEAREA (0 0)(100 100)
ROW row_1 siteA 1000 1000 N DO 100 BY 1 ;
TRACKS Y 540 DO 4192 STEP 540 LAYER METAL1 ;
```

## DSPF / RSPF / SPEF（附录 10A-C，p.259-266）

**用途**：SPF（Standard Parasitic Format）是 Cadence 公司开发的用于 EDA 工具间传递电路互连线寄生参数的标准接口格式，也是分析电路延时的重要依据。按信息完整程度分为原初 SPF、DSPF（Detailed SPF）与 RSPF（Reduced SPF）；SPEF（Standard Parasitic Exchange Format）是 IEEE 1481-1999 标准格式，是 SPF 的变异格式之一，可描述多种寄生模型并支持 slew/延迟计算语言与名称映射。

### DSPF

**文件基本结构**：DSPF 采用与 SPICE 类似的语法，用 `SUBCKT` 与 `.ENDS` 定义电路，用 `R`、`C` 表示电阻电容，所有 SPF 特有命令前加 `*|`。文件通常包括文件头、电路定义、全局地线、线网寄生定义、子电路调用等部分。

**关键字段或语法片段**：

- `*|DSPF`、`*|DESIGN`、`*|DATE`、`*|VENDOR`、`*|PROGRAM`、`*|VERSION`、`*|DIVIDER`、`*|DELIMITER`：文件头。
- `.SUBCKT` / `.ENDS`：子电路定义与结束。
- `*|GROUND_NET`：全局地线。
- `*|NET`：线网寄生信息，其后为总电容值。
- `*|P`：与线网相连的电路端口。
- `*|I`：与线网相连的子电路端口。
- `*|S`：子节点名称与坐标。
- `R`、`C` 元件语句。
- `X` 子电路调用。

### RSPF

**文件基本结构**：RSPF 也是 SPICE 类语法，但将线网寄生参数等效为驱动与负载模型，以提高仿真速度。驱动部分可等效为集总 C、集总 RC 或 Pi 模型；负载部分等效为压控电压源与电阻、电容。

**关键字段或语法片段**：

- `*|RSPF`、`*|DESIGN`、`*|DATE`、`*|VENDOR`、`*|PROGRAM`、`*|VERSION`、`*|DIVIDER`、`*|DELIMITER`：文件头。
- `*|NET`：线网名及总电容。
- `*|DRIVER`：驱动源端口。
- `*|S`：驱动端看到的子节点。
- `*|LOAD`：负载端口。
- `R`、`C`、`E` 等效元件。
- `X` 子电路调用。

### SPEF

**文件基本结构**：SPEF 不再使用 SPICE 语法，所有关键字以星号 `*` 开头。它支持多种互连线寄生模型、信号 slew/延迟计算语言、名称映射以及模块调用，分为五大部分：文件及设计基本属性、名称映射、电源/地线定义、端口定义、线网定义。

**关键字段或语法片段**：

- `*SPEF`、`*DESIGN`、`*DATE`、`*VENDOR`、`*PROGRAM`、`*VERSION`、`*DESIGN_FLOW`、`*DIVIDER`、`*DELIMITER`、`*BUS_DELIMITER`：文件头。
- `*T_UNIT`、`*C_UNIT`、`*R_UNIT`、`*L_UNIT`：单位定义。
- `*NAME_MAP`：名称映射，用整数代替长名。
- `*POWER_NETS` / `*GROUND_NETS`：电源/地线定义。
- `*PORTS`：电路端口，含 `*C`、`*L`、`*S`、`*D` 等可选属性。
- `*DEFINE` / `*PDEFINE`：调用外部寄生文件（逻辑块/物理块）。
- `*D_NET` / `*R_NET`：分布/缩减线网定义。
- `*CONN`、`*I`、`*P`、`*CAP`、`*RES`、`*END`：线网连接与寄生 R/C。
- `*DRIVER`、`*CELL`、`*C2_R1_C1`、`*LOADS`、`*RC`：缩减模型细节。

## SDF（附录 11，p.267）

**用途**：SDF（Standard Delay Format）由 OVI 组织制定，最新为 3.0 版。文件由后端工具产生，描述布局布线后单元及互连线的延时数据，主要用于将真实延时反标（back annotation）回前端仿真工具，进行门级网表时序功能验证；也可作为时序约束正标（forward annotation）用于综合与布局布线，但现多由 SDC 替代。

**文件基本结构**：SDF 文件由起始部分（header）与若干 `CELL` 部分组成。每个 `CELL` 的时序数据只对自身作用域有效，单元可以是芯片中的标准单元，也可以是整个芯片。`DELAY` 与 `TIMINGCHECK` 分别表示延时定义和时序检查定义。由于信号跳变情况不同，延时可包含 0→1、1→0、0→Z、Z→1 等最多 12 种转换情况，每种情况又可分为最小（minimum）、典型（typical）、最大（maximum）三种值。

**关键字段或语法片段**：

- `(SDFVERSION "3.0")`、`(DESIGN ...)`、`(DATE ...)`、`(PROGRAM ...)`、`(DIVIDER /)`、`(VOLTAGE ...)`、`(PROCESS ...)`、`(TEMPERATURE ...)`、`(TIMESCALE ...)`：文件头。
- `(CELL ...)`、`(CELLTYPE ...)`、`(INSTANCE ...)`：作用域定义。
- `(DELAY ...)`：延时定义，常用 `(ABSOLUTE ...)`。
- `(IOPATH ...)`：单元输入到输出延时，值格式为 `min:typ:max`。
- `(PORT ...)`：端口输入延时。
- `(INTERCONNECT ...)`：两端口间互连线延时。
- `(DEVICE ...)`：指定实例的延时。
- `(COND ...)` / `(CONDELSE ...)`：条件延时。
- `(TIMINGCHECK ...)`：时序检查，如 `(SETUP ...)`、`(HOLD ...)`、`(SETUPHOLD ...)`。

书中示例：

```text
(INSTANCE a)
  (TIMINGCHECK
    (SETUP din(posedge clk)(12))
  )

(INSTANCE a)
  (TIMINGCHECK
    (HOLD din(posedge clk)(9.5))
  )

(INSTANCE a)
  (TIMINGCHECK
    (SETUPHOLD (COND ~reset din)(posedge clk)(12)(9.5))
  )
```

## CPF（附录 12，p.270）

**用途**：CPF（Common Power Format）由 Cadence 于 2006 年发布，是专门针对低功耗设计的约束文件，基于 TCL 格式。它用于表达电源关断（PSO）、多供电多电压（MSV）、状态保持电源门控（SRPG）等低功耗技术，以覆盖从验证、综合、测试、物理综合、布线到签核的全流程。

**文件基本结构**：CPF 命令不多，不同工具支持略有差异，大致可分为 7 类：版本命令、库指定命令、库单元相关命令、作用域命令、通用命令、设计约束命令、设计实现约束命令。

**关键字段或语法片段**：

1. 版本命令：`set_cpf_version`
2. 库指定命令：`define_library_set`、`define_ecsm_libraries`
3. 库单元相关命令：`define_always_on_cell`、`define_isolation_cell`、`define_level_shifter_cell`、`define_power_switch_cell`、`define_state_retention_cell`
4. 作用域命令：`set_top_design`、`set_scope`
5. 通用命令：`set_array_naming_style`、`set_hierarchy_separator`、`set_register_naming_style`
6. 设计约束命令：`create_analysis_view`、`create_power_mode`、`create_delay_corner`、`create_operating_condition`、`update_delay_corner`
7. 设计实现约束命令：`create_isolation_logic`、`create_ground_nets`、`create_level_shifter_logic`、`create_power_ground_connection`、`create_power_nets`、`create_power_domain`、`create_power_switch_logic`、`create_state_retention_logic`、`identify_power_logic`

其中库单元相关命令用于声明 Liberty 时序库中与低功耗技术相关的特殊单元，包括常通单元（always on cell）、隔离单元（isolation cell）、电平转换单元（level shifter cell）、电压开关单元（power switch cell）和状态保持单元（state retention cell）。

## TCF（附录 13，p.271）

**用途**：TCF（Toggle Count Format）是 EDA 工具对电路进行精确功耗分析和优化的辅助文件，由前端设计人员在电路测试仿真阶段产生。文件记录 testbench 激励仿真时间内所有线网（net）和端口（pin）的平均逻辑“1”概率与逻辑翻转次数。

**文件基本结构**：TCF 文件由基本属性与实例数据两部分组成，分打平（flat）与层次化两种格式。文件头以 `tcffile()` 起始，其后定义版本、工具、日期、仿真时间与单位；数据部分以 `instance()` 起始，内部包含 `pin()` 与 `net()`。

**关键字段或语法片段**：

- `tcffile()`：文件头块。
- `tcfversion`、`generator`、`genversion`、`date`、`duration`、`unit`：版本、工具、时间、单位。
- `instance()` / `pin()` / `net()`：实例、端口、线网数据。
- 数据格式：`"name" : "probability toggle_count"`。

书中打平格式示例：

```text
tcffile () {
  tcfversion : "1.0";
  generator  : "RTL Compiler Low Power Verilog PLL";
  genversion : "1.0";
  date       : "Thu Nov 17 07:32:25 2006";
  duration   : "1.054150e+06";
  unit       : "ns";
}
instance(){
  pin() {
    "I0/I1/I0_3/i_1/A" : "0.692751 131348";
    "U1/U2_1/pin_a"    : "0.658988 144940";
    ...
  }
  net(){
    "U1/net_1" : "0.006443 9530";
    "U1/net_2" : "0.970150 19190";
  }
}
```

层次化格式不使用 `/` 作为层次分隔符，而是以 `instance()` 关键字嵌套寻址。每条记录中两个数值分别表示该节点在仿真时间内逻辑为“1”的概率以及逻辑翻转次数，例如 `"U1/U2_1/pin_a" : "0.658988 144940"` 表示该端口逻辑“1”的概率为 0.658988，翻转次数为 144940 次。

## TWF（附录 14，p.273）

**用途**：TWF（Timing Window Format）是 Cadence 延时计算工具分析信号噪声对延时影响的辅助文件。噪声影响取决于互连线间耦合电容大小与信号转换时间，而是否真正影响延时取决于相邻信号是否在同一时间段内跳变。TWF 记录每条信号线可能的跳变时间段与转换速率，每个信号最早/最晚跳变时间形成一扇“窗口”。

**文件基本结构**：TWF 语法比较简单，除文件基本属性外，关于时序窗的描述有两种格式：基于线网（NET）与基于端口（PIN），两者参数含义一致。

**关键字段或语法片段**：

- `NET <netName>` / `PIN <pinName>`：窗口对象。
- `minRTW / minFTW`：上升/下降信号最早发生时间。
- `maxRTW / maxFTW`：上升/下降信号最晚发生时间。
- `minRt / minFt`：最小上升/下降转换时间。
- `maxRt / maxFt`：最大上升/下降转换时间。
- `minRDr / minFDr`：最小上升/下降信号源电阻。
- `maxRDr / maxFDr`：最大上升/下降信号源电阻。
- `riseSlack / fallSlack`：上升/下降剩余时间（部分文件不定义）。

书中 NET 格式示例：

```text
(NET "m128out[3]"
  3.01e-09; 4.63e-09 6.49e-11; 6.52e-11 500; 502 *
  3.06e-09; 4.79e-09 5.04e-11; 5.06e-11 391; 393 *
)
```

上述示例中每行依次给出上升信号与下降信号的最早/最晚发生时间、最小/最大转换时间、最小/最大信号源电阻以及剩余时间。`riseSlack` 与 `fallSlack` 未定义时用 `*` 表示。
